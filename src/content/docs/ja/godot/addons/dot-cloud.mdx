サーバーがクライアントにマニフェストを渡し、クライアントは足りないものを
ダウンロードし、検証し、マウントします。Windows、macOS、Linux、Android、iOS、
そしてブラウザーで。

```gdscript
var cloud := DotCloudClient.new()
add_child(cloud)

cloud.config = DotCloudConfig.new()
cloud.config.trusted_keys = {"default": PUBLIC_KEY_PEM}
await cloud.start()

cloud.phase_changed.connect(func(_p, text): status_label.text = text)
cloud.progress_changed.connect(func(p): bar.value = p.fraction * 100.0)

var res := await cloud.acquire("https://cdn.example.com/dm_arena/manifest.json")
if res.ok:
    get_tree().change_scene_to_file(res.value)
```

公開はヘッドレスの CLI で行い、出力は**静的なディレクトリー**です。
`manifest.json` と `objects/` ツリーだけなので、どんな web サーバーや CDN でも
設定なしで配信できます。

```bash
godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    keygen --private keys/content.key --public keys/content.pub

godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    publish --source content/dm_arena --out dist/dm_arena \
    --id dm_arena --version 1.2.0 --entry arena.tscn --key keys/content.key
```

## すべてを形作った 2 つの制約

**Godot はリソースパックをアンマウントできません。** ゆっくりでも、回避策でも
なく、API が存在しません。そこで各コンテンツセットにはバージョンつきの独自パス
`res://<root>/<content_id>/<version>/` を与え、何かを置き換える必要が生じない
ようにしています。「アンロード」は参照を手放すことであって、ファイルテーブルを
取り戻すことではありません。この 1 点こそが、実行中のゲーム切り替えを成り立たせて
います。

**署名されていないコンテンツはリモートコード実行です。** Godot のパックには
スクリプトを入れられるので、何が実行されるかはマニフェストが決めます。
`require_signed_manifests` は既定で有効で、信頼できる鍵が無ければ設定の検証自体を
拒否します。LAN や自前サーバー向けに切ることもできますが、毎回警告が出ます。

## できること

- **内容アドレス方式のキャッシュ。** ファイルは SHA-256 の下に置かれるので、
  同じアセットを共有する 2 本のゲームはそれを 1 度だけダウンロードし、再公開時は
  変わった分だけ再取得します。
- **再開可能な並列ダウンロード。** ミラー切り替え、HTTP レンジによる再開、
  ソースごとのサーキットブレーカー、帯域制限、そして正直な進捗と残り時間。
- **3 種類のソース。** HTTP/CDN、ローカルディレクトリー（開発・LAN・同梱
  コンテンツ）、そして web ホストを持たないサーバー向けにゲーム接続を通す
  インバンド。
- **容量への配慮。** ブラウザーのストレージ見積り、モバイル向けの上限、そして
  使用中のコンテンツは決して追い出さない LRU 方式の退避。

## マウント時に検査されること

ダウンロードからマウントまでのあいだ、パックは 4 つのルールで検査されます。どれも、
誰かが計測した失敗から生まれたものです。

- **まず `requires.json` を読みます。** パックのスクリプトはホストのアドオンに対して
  コンパイルされるので、より新しいアドオンを必要とするパックは、読み込みの途中で
  パースに失敗していました。今はスクリプトが 1 つも読み込まれる前に拒否され、
  *「このゲームには dot-net の API レベル 3 以上が必要です。このビルドは
  レベル 2 です」* と表示されます。
  [アドオン API レベル](/learn/godot/addons/dot-core#addon-api-levels-dotaddonapi)を
  参照してください。`host_role` がどちら側かを指定します。
- **コンテンツ id は所有者の名前を含められます。`<owner>/<name>`。** `/` はどちらの
  半分にも現れないので、`alice/*` にスコープされたキーは厳密です。平坦化された
  `alice_bob` では、`alice` + `bob_x` と `alice_bob` + `x` を区別できません。各
  セグメントはスラッグでなければなりません。first-party のパックすべてがそうである
  素の id も、引き続き有効です。
- **1 つの id が 2 つの意味を持つことはできません。** 同じ
  `content_id@version` に対する、別の公開者からの 2 つ目のマニフェストは、最初の
  もののマウントを渡されるのではなく `CODE_CONFLICT` で拒否されます。パックには
  スクリプトを入れられ、「最初のもの」は他人のコードだからです。通信路から再読み込み
  された同一のマニフェストは、従来どおり安価な何もしない処理です。
- **マウントされたパックは自分の uid を登録しますが、他人のものを奪ってはなりません。**
  インポートされたアセット（`.glb`、`.png`）は兄弟アセットを UID で参照しますが、
  それは別の場所にマウントされると失われます。マウンターは各 UID をマウントされた
  コピーに向け直します。ホストがすでに持っている UID は拒否されて報告されます。
  そうしないと、ビルド内のすべての `load("uid://…")` がダウンロードされた
  コンテンツに向け直されかねないからです。

<Callout type="warning" title="インポート済み出力は `.godot/` ではなく `_imported/` の下で配布されます">
公開されたパックにはエンジンのインポート済み出力が入っていて、以前は実際のパスである
`.godot/imported/` に置かれていました。Linux ではそれが完璧に読み戻せますが、**web
エクスポートでは読めず**、ゲーム全体がブラウザーで起動を拒否していました。出力は
今は `_imported/` の下で配布され、各 `.import` マーカーは出力の置き場所を指すよう
書き換えられます。そうしないと、マウントされたパックのアートの欠落は警告としてしか
現れず、パックは検証され、マウントされ、読み込まれ、テクスチャーだけが無い状態に
なります。
</Callout>

## ゲームが差し込める場所

<Params>
  <Param name="DotCloudSource のサブクラス">
    `source_name()`、`is_supported()`、`can_serve(manifest)`、`fetch(...)`。
    3 つが同梱されています——`DotCloudSourceHttp`、`DotCloudSourceLocal`、
    `DotCloudSourceNetchan`——4 つ目はあなたのものです。torrent、プラットフォーム
    固有の CDN、署名付き S3 URL の発行元など。

    `fetch` は**必ず**、そのファイルのハッシュに対応する
    `DotCloudStore.partial_path` に書き、可能なら `partial_size` から再開し、
    `commit_partial` で完了させてください。ハッシュが検証されるのはそこだけで、
    オブジェクトディレクトリーへ直接書くのは、検証されていないコンテンツが
    マウントされる典型的な経路です。
  </Param>
  <Param name="can_serve() と is_supported() の違い">
    この区別は元が取れています。ソースが完全に健全でも、*この*マニフェストには
    到達手段が無いことがあります。`base_urls` の無い HTTP ソースと、ミラーを
    持たないマニフェストの組み合わせがそれです。`can_serve` から失敗を返すのは
    「このマニフェストでは自分を飛ばしてくれ、理由はこれだ」という意味で、
    サーキットブレーカーの失敗としては**数えられません**。
  </Param>
  <Param name="priority" type="int">
    すべてのソースにあります。小さいほうが先に走り、インバンドのフォールバックは
    意図的に最後です。
  </Param>
  <Param name="DotCloudConfig">
    `trusted_keys`、`require_signed_manifests`、`cache_bytes`、
    `mobile_cache_bytes`、`web_quota_fraction`、`parallel_downloads`、
    `max_attempts_per_file`、`throttle_bytes_per_sec`、`file_timeout_sec`、`cache_dir`、
    `verify_before_mount`、`verify_cache_on_start`、`resume_downloads`、
    `enforce_mount_prefix`。どの `DotConfig` とも同じく階層化されています。
  </Param>
  <Param name="manifest_url_template / manifest_url_fallbacks" type="DotCloudClient">
    ベース URL、id、バージョンからマニフェストをどこに求めるか。既定は `{base}/{id}/{version}/manifest.json` で、サイトが公開する形です。`manifest_url_fallbacks` は、それに続けてベースごとに試す別の形の一覧です。1 つの配信元に 2 種類のレイアウトで公開されたパックが混在しうるため、すべてを再公開することを起動の前提条件にはしないからです。
  </Param>
  <Param name="シグナル">
    `DotCloudClient` では `phase_changed`、`progress_changed`、`content_ready`、`content_released`、`failed`。ファイルごとの詳細はダウンローダー側にあります。`file_finished`、`sync_finished`。
  </Param>
</Params>

## 他のアドオンが期待するコンテンツ用インターフェース

`DotCloudClient` を登録すると、`dot_cloud_client` という名前で自分を公開します。
`dot-map` のローダーと `dot-server` のゲーム切り替えは、その名前で到達して次を
呼びます。

```gdscript
ensure(content_id: StringName, version: String = "", groups := PackedStringArray(), manifest_url := "") -> DotResult
is_mounted(content_id: StringName, version: String = "") -> bool
```

ほとんどのアドオンは、
[`dot-core`](/learn/godot/addons/dot-core#downloadable-content-dotcontent) の
`DotContent`——共有の呼び出し口——経由でこれらに到達します。アバターのパーツ、
プロップ、NPC、乗り物、アイテムがコンテンツ名を持つときに、実際にそれを取得する
のはそのおかげです。

<Callout type="warning" title="クラウドクライアントが無い構成も正当です">
どの呼び出し側も「`dot_cloud_client` が無い」を「このデプロイはコンテンツを
ビルドに同梱している」と解釈します。自分のゲームにとっては正当な選択で、したがって登録に失敗した
クライアントと区別がつきません。TMC 自身のデプロイはビルドにコンテンツを一切同梱せず、すべてのゲーム、インポートされたすべてのマップ、そしてロビーがこのアドオンの取得するパックです。配信されたマップやゲームが無言で何もしないときは、
まずレジストリーを見てください。
</Callout>
