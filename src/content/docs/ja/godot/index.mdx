**Dot** は The Modding Community の Godot 4 アセットコレクションです。22 個の
アドオン、シェルランチャー、サーバーツール、そしてアドオン群を組み合わせて動かす
ために存在する 5 本のゲームからなります。サイトでは
[Dot アセットコレクション](/co/4-dot-assets)として、GitHub では
[`modcommunity`](https://github.com/modcommunity) 配下にあります。

これらは、エンジンの機能ではない部分——アカウント、アバター、コンテンツ配信、
ネットコード、専用サーバー、モデレーション、タイマー、ランキング——を、
**素の Godot の上に載せるレイヤー**として提供します。どれも要らないゲームは、
ただの Godot プロジェクトのままで構いません。

## Godot をフォークはしません

最初に片付けておく価値があります。「Godot のフォーク」と「Godot のアドオン」は
別々のプロジェクトへ向かい、完成させられるのは片方だけだからです。

フォークするということは、エンジンのリリース周期、6 プラットフォーム分の
エクスポートテンプレート、web ビルド、そして未来永劫のリベースを引き受けると
いうことです。しかも分岐した瞬間、そのフォーク向けに書かれたゲームは Godot の
アセットライブラリから何も使えなくなります。人が「プラットフォーム」と言うときに
本当に指しているものは、エンジンの機能ではありません。身元、アバター、コンテンツ
配信、専用サーバー、モデレーション、発見性。そのどれもがエンジンの*上*のレイヤー
です。

つまり **素の Godot、プラス アドオン、プラス 1 つのオープンなバックエンド
プロトコル** です。

## 強い依存は常に `dot-core` だけ

これはコレクション全体が拠って立つルールであり、GDScript ではただの好みでは
ありません。**プロジェクトに存在しない `class_name` を*言及しただけ*の
スクリプトはパースに失敗し**、それを参照しているスクリプトすべてを道連れに
します。あるアドオンが別のアドオンを import すれば、その別のアドオンは全員に
とって必須になってしまいます。

そこで、それ以外はすべて実行時に発見するか、ダックタイピングするか、ゲーム側で
橋渡しします。

- `dot-server` は
  [`DotRegistry`](/learn/godot/conventions#dotregistry-instead-of-autoloads)
  経由で `dot-auth` と `dot-cloud` を見つけ、どちらも import しません。
- `dot-net` は `dot-core` だけを必要とし、バイト列は `Callable` で受け渡します。
- `dot-fps-controller`、`dot-combat`、`dot-loadout`、`dot-match`、`dot-2d` は
  それぞれ `*NetSync` クラスを持ち、何をレプリケートするかを**データとして**
  ——プロパティ名と型名を*文字列*で——記述します。橋渡し側が
  `DotNetVar.Type[spec.type]` で解決します。どれも `dot-net` の識別子を
  書きません。
- `dot-combat` はラグ補償を 2 つの `Callable` として受け取ります。
- `dot-ui` は `dot-core` の外を一切名指ししません。フィードは色付き断片を受け取り、
  テーブルは辞書の行を受け取ります。
- `dot-user` と `dot-user-avatar` は互いを import せず、`dot-loadout` も同じ
  理由でストレージキー検査の写しを自前で持っています。

<Callout type="info" title="ここでの重複は意図的です">
2 つのアドオンが同じ 20 行を抱えているとき、それは上のルールの代価であって
見落としではありません。共有 import にまとめることこそ、あるアドオンが別の
アドオンの依存になる道筋です。
</Callout>

## 部品の積み上がり方

```
                        ┌──────────────┐
                        │   dot-core   │  logging, capabilities, paths,
                        │              │  node refs, config, jobs,
                        └──────┬───────┘  transports, HTTP
      ┌───────────┬────────────┼────────────┬───────────┬──────────┐
      ▼           ▼            ▼            ▼           ▼          ▼
┌───────────┐ ┌──────────┐ ┌─────────┐ ┌──────────┐ ┌────────┐ ┌────────┐
│ dot-cloud │ │ dot-auth │ │ dot-net │ │dot-server│ │ dot-ui │ │ dot-2d │
└─────┬─────┘ └────┬─────┘ └─────────┘ └────┬─────┘ └────────┘ └────────┘
      │            │                        │
┌─────┴─────┐ ┌────┴───────────┐    ┌───────┴────────┐
│ dot-user  │ │dot-user-avatar │    │  dot-platform  │
└───────────┘ └────────────────┘    └────────────────┘

      ┌──────────────────┬──────────────┬─────────────┐
      ▼                  ▼              ▼             ▼
┌────────────┐    ┌────────────┐  ┌───────────┐ ┌──────────────────┐
│ dot-combat │    │dot-loadout │  │ dot-match │ │dot-fps-controller│
└────────────┘    └────────────┘  └───────────┘ └──────────────────┘
      └──────────────────┴──────────────┴─────────────┘
                               │  ここにあるものはどれも
                               ▼  dot-core だけを必要とします
                    ┌──────────────────────┐
                    │      あなたのゲーム    │  橋はここに書かれます
                    └──────────────────────┘
```

矢印は最上段を除いてすべて*任意*の関係です。「必須」ではなく「あると良い」と
読んでください。

## 3 つのグループ

**プラットフォーム側** — `dot-core`、`dot-cloud`、`dot-auth`、`dot-net`、
`dot-server`、`dot-user`、`dot-user-avatar`、`dot-platform`。プレイヤーが誰で、
どう見えて、どうコンテンツを手に入れ、どの専用サーバーに繋ぐか。

**ゲームプレイ側** — `dot-fps-controller`、`dot-2d`、`dot-combat`、
`dot-loadout`、`dot-match`、`dot-ui`。移動、武器、装備、試合ループ、
インターフェース。どれも `dot-core` だけで動きます。

**ジャンルキット** — `dot-timer`、`dot-map`、`dot-props`、`dot-leaderboard`、
`dot-stats`、`dot-voice`、`dot-moderation`、`dot-vote`。人がまた戻ってくる
*サーバーを運営する*のに必要なものすべて。記録表、マップローテーション、次に何を
遊ぶかの投票、セッションをまたいで残る処罰。

## ジャンルキットは機能一覧ではなく戦略です

このコレクションの問題は機能不足だったことは一度もありません。問題は、
**新しいプラットフォームに最初に乗る理由が誰にもない**ことで、汎用のアドオン
ファミリーはその理由を与えません。ジャンルは与えます。

選ばれたのは surf と bunny-hop——Counter-Strike の移動コミュニティです。2026 年
になっても、2013 年に最後に開かれた SDK 向けに書かれたタイマープラグインで
Source サーバーを回し続けています。最初のジャンルとして良い理由は 4 つあり、
私たちの都合なのは 4 つ目だけです。

1. **移動は最も正しく作るのが難しい。** Quake の加速と Source の
   `TryPlayerMove` を、10 年 surf をやってきた人が違いに気づかないほど忠実に
   再現できる人はほとんどいません。
2. **サーバーの形をしている。** surf コミュニティ*そのもの*がサーバーです。
   ローテーション、記録表、新しいマップをゾーン分けする管理者、ランキングを気に
   する常連。
3. **コンテンツが可搬でコミュニティ製。** マップはマッパーから、ゾーンは管理者
   から来て、どちらもファイルとしてやり取りされます。
4. **完成させられるだけ小さい。** アドオン 4 つと遊べるゲーム 1 本。

## バックエンド以外はすべて MIT

アドオン、ゲーム、ツールはすべて MIT ライセンスのオープンソースです。唯一そうで
ないのが **web バックエンドのインフラ**、つまり TMC 自身の運用環境です。それと
通信するアドオンはいずれも文書化された HTTP プロトコルを使い、変更可能な
`backbone_url` を指しているので、独自バックエンドが欲しいプロジェクトはそれを
作って設定を 1 つ変えるだけです。
