**このコレクションの何ひとつとして、フォークを必要とすべきではありません。**
以下のいずれかのポイントに到達しづらくなる変更は、テストが全部通っていても
リグレッションとして扱われます。

拡張ポイントには 5 種類あり、どれを見ているかが分かれば、どこを探せばよいかも
分かります。

<Params>
  <Param name="基底クラスを継承する">
    オーバーライドすべき `_` 接頭辞のメソッド群が文書化された抽象クラス。ストア、
    ソース、コーデック、ルール、画面、モジュール。全部で 30 ほどあります。
  </Param>
  <Param name="Callable を代入する">
    ノード上のフィールドで、たいてい `*_fn` か `*_source` という名前です。
    アドオンが意図的に自分では答えないただ 1 つの問いに答えます。プレイヤーが
    どこにいるか、どのチームか、バイト列をどこへ送るか。約 50 個。
  </Param>
  <Param name="Resource を作る">
    デザイナーがインスペクターで編集する `.tres`。移動パラメーター、スキーマ、
    カタログ、ルール、スタイル、路面。コードは一行も要りません。
  </Param>
  <Param name="レジストリ名で公開する">
    ダックタイピングの継ぎ目。合意された名前でメソッドを 1 つ持つオブジェクトを
    登録すれば、2 つのアドオンは互いを import せずに協調します。
  </Param>
  <Param name="設定を重ねる">
    すべての `DotConfig`。エクスポートされた既定値、次に JSON か YAML のファイル、
    次に環境変数、次にコマンドライン。
  </Param>
</Params>

## 索引の全体

| 変えたいこと | 場所 |
| --- | --- |
| コンポーネントがどのノードに付くか | 各コンポーネントの `DotNodeRef` |
| コンテンツの入手元（CDN、ディスク、インバンド） | `DotCloudSource` のサブクラス |
| プレイヤーの認証方法（Steam、Epic、自前） | `DotAuthProvider` のサブクラス、`DotAuthServer.add_provider` |
| BAN の保存先（共有 DB、HTTP サービス） | `DotBanManager` に付ける `DotBanStore` のサブクラス |
| サイトのグループ → サーバー権限 | `DotAuthAdminSource`、または `lookup()` / `source_name()` を持つ任意のオブジェクト |
| サーバーのコマンドとふるまい | `DotModule` のサブクラス、または `DotConsole.command` |
| サーバークエリがゲームについて何を返すか | `DotQueryProvider`、または `DotModule.add_query_provider` |
| 何かに反応する、あるいは拒否する | `DotEventBus.hook_pre` / `hook_post` |
| 何をどの精度でレプリケートするか | `DotNetVar` の宣言。任意の型は `Type.CUSTOM` |
| シミュレーション、操作、メッセージ | `DotNetBehaviour`、`DotNetInput`、`DotNetMessage` のサブクラス |
| 誰に何を見せるか | `DotNetInterest` のサブクラス |
| エンティティの生成方法 | `DotNetSpawner.register_factory` |
| バイト列の行き先 | `DotNetManager.send_fn`、`DotTransport` のサブクラス |
| 音声の入力元と出力先 | `DotVoiceSource` / `DotVoiceSink` のサブクラス |
| 音声コーデック | `DotVoiceCodec` のサブクラス、`DotVoiceCodec.register` |
| 誰の声が誰に届くか | `DotVoiceRouter.team_fn` / `position_fn` / `listener_filter` |
| そもそも誰が話せるか | `dot_mute_source` に登録された `is_voice_muted(peer)` を持つもの |
| 処罰の保存先 | `DotPunishmentStore` のサブクラス |
| どのデータベースに入れるか | `DotSqlDriver` のサブクラス、または `DotPunishmentStoreRest` |
| ピアと人物の対応づけ | `DotModerationManager.key_for_peer` |
| どの BAN リストを適用するか | `dot_ban_source` として登録されたもの |
| 1 つのアドレスが持てるクライアント数 | `sv_max_connections_per_ip`、`DotAddressGuard` |
| モデレーターがプレイヤーを指定する方法 | `DotServer.find_sessions` — 名前、ユーザー名、id、`ip:`、`@me` |
| プレイヤーの位置と移動のさせ方 | `DotModTools.position_fn` / `teleport_fn` |
| プレイヤーが参加したときの処理 | `DotPlatformModule`、または `DotPlatformHub.admit` を直接 |
| 所有権（エンタイトルメント）の出どころ | `DotPlatformHub.entitlement_source` |
| プロフィールの保存先 | `DotUserManager` に付ける `DotUserStore` のサブクラス |
| 名前として何が許されるか | `DotUserManager.name_filter` |
| プレイヤーが着られるもの | `DotAvatarSchema` + `DotAvatarEntitlements` |
| アバターの保存先 | `DotAvatarStore` のサブクラス |
| パーツ id からアセットへの解決 | `DotAvatarCatalogue.resolver` |
| 移動の手触り | `DotFpsTunables`。インスタンスごと、または JSON ファイルで |
| 名前付きの変種 — 横向き、低重力、prebhop | `DotFpsStyle` + `DotTimerStyle`（id で対応づけ） |
| ある種類の地面のふるまい | `DotFpsSurfaceSet` の中の `DotFpsSurface` |
| 一時的な変化 — 加速板、スタン、射出装置 | `DotFpsModifier` |
| まったく新しい移動手段 — はしご、水中、グラップル | `DotFpsMoveMode` のサブクラス |
| プレイヤーが何に当たるか | `DotFpsController._make_body` 経由の `DotFpsBody` サブクラス |
| 入力デバイス、ボット、デモ再生 | `DotFpsSampler` / `Dot2DSampler`、または自分でコマンドを組み立てる |
| タイマーが世界の何に反応するか | `DotTimerZone.Kind`。エディターで描くか `DotTimerZonePainter` で |
| 記録とランキングの保存先 | `DotTimerStore` / `DotLeaderboardStore` のサブクラス |
| マップとは何か、次に何が来るか | カタログ内の `DotMapDef`。`DotMapRotation`、`DotMapVote` |
| マップ変更をクライアントに届ける方法 | `DotMapSyncHost.send_fn` / `DotMapSyncClient.send_fn` |
| ホストの指示でクライアントが何を読み込むか | `DotMapSyncClient.accept_unknown_maps` |
| 投票のあらゆる方針 | `DotVoteRules`。55 個の設定で、どの `DotConfig` とも同じく階層化 |
| 何に投票できるか、「これを遊ぶ」とは何か | `DotVoteSource` のサブクラス、または `DotVoteGameSource` / `DotVoteMapSource` / `DotVoteListSource` |
| 投票で誰がプレイヤー・管理者・観戦者か | `DotVoteDirector.player_count_fn` / `is_admin_fn` / `is_spectator_fn` |
| 1 票の重み | `DotVoteDirector.weight_fn` |
| 投票コマンドの名前 | `DotVoteCommands.prefix` / `names` |
| 何をいくつ設置できるか | `DotPropCatalogue`、`DotPropLimits` |
| 新しいサンドボックス用ツール、あるいは武器 | `DotPropTool` のサブクラス |
| コードを持つプロップ | `DotPropDef.meta.script`（パス指定） |
| 武器とは何か | `DotWeapon`、傷つけ方は `DotDamageType` |
| 弾がどこへ飛ぶか | `DotTrace` のサブクラス — `DotTracePhysics` か `DotTraceFlat` |
| 名前付きの部位と倍率 | `DotHitGroup`。列挙ではなくテーブル |
| フレンドリーファイア、自傷、上限 | `DotDamageRules` と `DotDamageResolver.adjust` |
| ラグ補償を有効にする | `DotCombatManager.rewind_fn` / `restore_fn` の 2 つの callable |
| アイテムとは何か、どこに何が入るか | `DotItem`、`DotLoadoutSlot`、`DotLoadoutSchema` |
| ロードアウトの保存先 | `DotLoadoutStore` のサブクラス |
| 勝利とは何か | `DotMatchRules` のサブクラス — `_round_outcome`、`_round_winner` |
| プレイヤーがどこに出現するか | `DotSpawnPoint`、`DotSpawnSelector.danger_fn` / `filter_fn` |
| 画面とは何か | `DotScreenStack` に登録する `DotScreen` のサブクラス |
| インターフェースの見た目 | `Theme`、または `DotUiTheme` のパレット。`dot-ui` は美術素材を持ちません |
| 設定画面の作り方 | 何も要りません。`DotSettingsPanel` があなたの `DotConfig` を読みます |
| 2D の物体の動き方 | `Dot2DTunables`、質量ベースなら `Dot2DMassRules` |
| 2D の物体が何に当たるか | `Dot2DBody` のサブクラス |
| フレームを止めずに長い処理をする | `DotScheduler` に載せる `DotJob` のサブクラス |
| ログの行き先 | `DotLogSink`、または `Callable` を渡す `DotLog.add_sink` |

## アドオン別の継承ポイント

いずれも小さく文書化されたメソッド集合を持つ抽象基底クラスです。**必須**と
書かれたものには有用な既定実装がありません。

<Params>
  <Param name="DotTransport" type="dot-core">
    **`_create_server`**、**`_create_client`**、`_transport_name`、
    `_is_available`、`supports_web_clients`、`scheme`。`_is_available` は使用前に
    確認されるので、失敗は起動時の「このビルドは ENet でホストできません」であって、
    3 回呼んだ先の null ピアではありません。
  </Param>
  <Param name="DotJob" type="dot-core">
    **`_step`**（有界な一区切り。まだ残っていれば true）、`_progress`（0..1、
    本当に不明なら **-1**。正直な不定バーのほうが、逆走するバーよりましです）、
    `_setup`、`_teardown`、`is_thread_safe`。
  </Param>
  <Param name="DotConfig" type="dot-core">
    `env_prefix`、`cli_prefix`、`sensitive_keys`、`validate`。
  </Param>
  <Param name="DotLogSink" type="dot-core">
    ログレコードのハンドラー。`DotLog.add_sink(callable)` は 1 行版です。
  </Param>
  <Param name="DotCloudSource" type="dot-cloud">
    `source_name`、`is_supported`、`can_serve(manifest)`、**`fetch`**。`fetch` は
    `DotCloudStore.partial_path` に書き、可能なら `partial_size` から再開し、
    `commit_partial` で完了しなければなりません。ハッシュが検証されるのはそこ
    だけです。オブジェクトディレクトリーへ直接書くのは、検証されていないコンテンツが
    マウントされる典型的な経路です。
  </Param>
  <Param name="DotAuthProvider" type="dot-auth">
    `_provider_name`、**`_handles(credential)`**（安価で純粋に構造的に）、
    **`_authenticate(credential)`**、`_validate`。credential を引き受けてから
    拒否したプロバイダーは判断を下したのであって、サーバーはそのあと別の
    プロバイダーに*回しません*。
  </Param>
  <Param name="DotNetBehaviour" type="dot-net">
    `_register_net_vars`、`_net_ready`、`_net_removed`、`_net_simulate`、
    `_net_state_applied`、`_net_interpolated`、`_net_read_property`、
    `_net_write_property`。ゲームが最も多く継承するクラスです。
  </Param>
  <Param name="DotNetInput" type="dot-net">
    **`_write`**、**`_read`**、`_sanitise`（クライアントが誇張しうるものを丸めます。
    量子化はすでに各フィールドを個別に制限しているので、ここで見るのはフィールド
    同士の*関係*です）、冗長送信を抑える `_equals`。
  </Param>
  <Param name="DotNetMessage" type="dot-net">
    **`_type_name`**（名前空間つき。あなたのものは `net.` で始めないでください）、
    **`_write`**、**`_read`**、`_validate`。検証はハンドラーではなく `_validate`
    で行ってください。検証するハンドラーは、誰かが検証を落としたままコピーする
    ハンドラーです。
  </Param>
  <Param name="DotNetInterest" type="dot-net">
    `_is_relevant`（たいていの戦略ではこれだけをオーバーライドします）、
    一括フィルターの `_candidates`、スナップショットごとに索引を作り直す
    `_prepare`、予算が厳しいときの優先度づけの `_score`。
  </Param>
  <Param name="DotModule" type="dot-server">
    **`_module_name`**、`_module_version`、`_module_description`、
    `_module_author`、**`_module_load`**、`_module_unload`、
    `_module_game_changed`。ヘルパー経由で登録したコマンド・cvar・フックは自動で
    取り消されます。タイマー、ファイル、ソケットのために `_module_unload` を
    オーバーライドしてください。
  </Param>
  <Param name="DotBanStore" type="dot-server">
    `_store_name`、**`_load`**、`_put`、`_remove`、`_refresh`、`_writable`。
  </Param>
  <Param name="DotQueryProvider" type="dot-server">
    `_provider_name`、**`_contribute(snapshot)`** — ゲームが自分の状態をサーバー
    クエリに載せる方法です。
  </Param>
  <Param name="DotUserStore / DotAvatarStore / DotLoadoutStore" type="dot-user, dot-user-avatar, dot-loadout">
    3 つとも同じ形です。**`_fetch`**、`_store`、`_remove`、`_open`、`_close`、
    `_writable`、`_store_name`。成功しての **null** は「このプレイヤーは持って
    いない」という意味で、エラーではありません。
  </Param>
  <Param name="DotPunishmentStore" type="dot-moderation">
    `store_name`、`is_writable`、**`load_all`**、`put`、`update`、`remove`。
    バックエンドがデータベースなら `DotSqlDriver`（`dialect`、`open`、`execute`、
    `query`、`batch`）と組み合わせます。
  </Param>
  <Param name="DotTimerStore / DotLeaderboardStore" type="dot-timer, dot-leaderboard">
    `put`、`top` / `page`、`best_for` / `entry_for`、`rank_of`、`count_on`、
    `remove`。並べ替えはマネージャーの仕事で、ストアがやる必要はありません。
  </Param>
  <Param name="DotMatchRules" type="dot-match">
    `_points_for_kill`、**`_round_outcome`**、`_round_winner`、`_respawn_delay`。
    `DotRulesElimination` は「これが何のためにあるか」を示す実例です。
  </Param>
  <Param name="DotTrace" type="dot-combat">
    **`_world_ray`** だけ。ヒットボックスの走査、壁を優先する同着処理、復元は基底
    クラスの担当です。
  </Param>
  <Param name="DotFpsBody / Dot2DBody" type="dot-fps-controller, dot-2d">
    `sweep` / `move`、`overlaps`、`describe`。モーターが必要とする衝突クエリで、
    決定性のためのフラットな解析実装と、実ジオメトリー用の物理実装があります。
  </Param>
  <Param name="DotFpsMoveMode" type="dot-fps-controller">
    `_name`、`_enter`、`_exit`、**`_simulate`**、`_uses_crouch`。はしご、水中、
    グラップルを、モーター自身の衝突と加速の上で。
  </Param>
  <Param name="DotVoiceCodec" type="dot-voice">
    `id`、**`encode`**、**`decode`**、`bytes_for`、`is_stateful`、`reset`、
    `duplicate_codec`。あとは `DotVoiceCodec.register(...)` を呼ぶだけで、他は何も
    変わりません。Opus の GDExtension が入るのはこの継ぎ目です。
  </Param>
  <Param name="DotVoiceSource / DotVoiceSink" type="dot-voice">
    `start`、`stop`、`has_frame` / `can_accept`、`read_frame` / `write_frame`、
    `is_running`。デバイスをインターフェースの裏に置いたことが、この経路全体に
    ヘッドレステストがある唯一の理由です。
  </Param>
  <Param name="DotVoteSource" type="dot-vote">
    `source_name`、**`choices`**、`current_id`、`supports_apply`、`apply`。何も
    変更できないソースも正当です。ディレクターが `change_due` を出し、ホストが
    動きます。
  </Param>
  <Param name="DotPropTool" type="dot-props">
    `effective_reach`、`target`、`may_act_on`。同梱のサブクラスは `DotPhysGun` と
    `DotGravGun` です。
  </Param>
  <Param name="DotScreen / DotHudWidget" type="dot-ui">
    `_screen_id`、`_on_push`、`_on_pop`、`_on_cover`、`_on_reveal`、`_can_pop`。
    ウィジェットには `_on_value`。`_can_pop` は控えめに使ってください。閉じるのを
    拒む画面は、プレイヤーを閉じ込められる画面です。
  </Param>
</Params>

## Callable のフック

アドオンは仕事のやり方を知っていますが、あなたの世界のことは知りません。以下は
アドオンが推測を拒む問いを、答える内容ごとにまとめたものです。

**バイト列の行き先。** `DotNetManager.send_fn`、`DotVoiceManager.send_fn`、
`DotVoiceRouter.send_fn`、`DotMapSyncHost.send_fn`、`DotMapSyncClient.send_fn`。
これらのアドオンはどれもソケットを所有しません。だからこそ `dot-net` はループ
バックでも、実トランスポートでも、あなた自身の実装でも動きます。

**何がどこにあるか。** `DotMatch.position_fn`、`DotVoiceRouter.position_fn`、
`DotModTools.position_fn` / `teleport_fn`。`DotModTools` が位置を `Variant` で
受けるのは意図的で、2D を回避対象ではなく一級の利用者にするためです。

**誰が何として数えられるか。** `DotDamageResolver.team_of`、
`DotVoiceRouter.team_fn` / `listener_filter`、
`DotVoteDirector.player_count_fn` / `is_admin_fn` / `is_spectator_fn` /
`voters_fn` / `weight_fn`、`DotRulesElimination.alive_fn`、
`DotModerationManager.key_for_peer`、`DotModTools.immunity_fn`。

**プレイヤーが何を持ち、何と名乗れるか。**
`DotLoadoutManager.entitlement_source`、`DotPlatformHub.entitlement_source`、
`DotUserManager.name_filter`、`DotItemCatalogue.resolver`、
`DotAvatarCatalogue.resolver`。

**弾がどこまで巻き戻るか。** `DotCombatManager.rewind_fn` / `restore_fn`。
2 行でラグ補償が有効になります。未設定なら射撃は現在時点に対して解決され、
リッスンサーバーでは正しく、遅延のある人にとっては誤りです。

**その他すべて。** `DotSpawnSelector.danger_fn` / `filter_fn`、
`DotDamageResolver.adjust`、`DotFpsMotor.surface_resolver`、
`DotPickupField.wants_fn` / `tags_fn`、`DotHudWidget.source`、
`DotStatBar.max_source`、`DotConVar.validator`、`DotConCommand.completer`、
`DotBackboneClient.roster_provider` / `stats_provider`、
`DotVoteDirector.announce_fn`、`DotVoteListSource.apply_fn`、
`DotVoiceManager.sink_factory`、`DotNetVar.read_fn` / `write_fn` /
`change_handler`、`DotNetSpawner.register_factory`。

<Callout type="warning" title="未設定のフックはエラーではありません">
これらのほとんどには、未設定時の筋の通ったふるまいがあります。だからこそ設定し
忘れは見つけにくいのです。`entitlement_source` を繋いでいなければプレイヤーは
何も所有しておらず、`rewind_fn` が未設定ならラグ補償は無く、`key_for_peer` が
未設定なら処罰が誤ったキーで管理されます。各アドオンの `describe_lines()` は
欠けているものを報告します。機能が壊れていると決めつける前に、まずそれを
読んでください。
</Callout>

## 自分で作るリソース

コードも継承も不要です。`.tres` か JSON ファイルだけ。

| リソース | 何を決めるか |
| --- | --- |
| `DotFpsTunables` | 移動のすべての数値。階層化: 既定値 < JSON < `DOT_FPS_*` < `--fps-*` |
| `DotFpsSurface` / `DotFpsSurfaceSet` | 氷、泥、ベルトコンベヤー。**倍率であって絶対値ではありません。** 基本の手触りを調整し直せば全体に伝わります |
| `DotFpsModifier` | 一時的な変化: 加速板、減速領域、スタン、射出装置 |
| `DotFpsStyle` | 名前付きの変種 — 横向き、後ろ向き、低重力、prebhop |
| `Dot2DTunables` / `Dot2DMassRules` | 見下ろし・推力・blob。そして質量が大きさ・速度・相手を食べる権利にどう変わるか |
| `DotWeapon` / `DotDamageType` / `DotHitGroup` | 武器とは何か、どう傷つけるか、ヘッドショットの価値 |
| `DotDamageRules` | フレンドリーファイア、自傷、距離減衰、上限を、1 つの順序で 1 度だけ |
| `DotItem` / `DotLoadoutSlot` / `DotLoadoutSchema` | ゲームモードの装備ルール |
| `DotAvatarSchema` / `DotAvatarSlot` / `DotAvatarPart` | どのパーツが存在し、どの値が正当か |
| `DotMatchRules` | 勝利とは何か、キルの価値はいくらか |
| `DotSpawnPoint` / `DotTeam` | プレイヤーの出現位置と所属 |
| `DotTimerZone` / `DotTimerZoneSet` / `DotTimerStyle` | タイマーが反応する対象と、ランク対象スタイルの定義 |
| カタログ JSON の `DotMapDef` | マップ: id、バージョン、シーン、必要ならコンテンツパック |
| `DotPropDef` / `DotPropCatalogue` / `DotPropLimits` | 何をいくつ設置できるか |
| `DotVoteRules` | 集計方式から同点処理まで 55 個の設定 |
| `DotLeaderboardDef` / `DotStatsSchema` | ボードが何で並ぶか、新しい値が古い値とどう出会うか |
| `DotUiTheme` | パレットとスケールから `Theme` 一式。アセットは不要 |

## レジストリの継ぎ目

以下のいずれかの名前でオブジェクトを公開すれば、別のものがそれを見つけます。
どちらの側も相手を import しません。

| 名前 | 公開するもの | 参照するもの |
| --- | --- | --- |
| `dot_ban_source` | `DotModerationManager` | `dot-server` の入場チェック |
| `dot_mute_source` | `DotModerationManager` | `DotVoiceRouter` |
| `dot_cloud_client` | `DotCloudClient` | `dot-map` のローダー、`dot-server` のゲーム切り替え、`dot-user-avatar` のカタログ |
| `dot_user_manager` | `DotUserManager` | `dot-server`、`dot-platform` |
| `dot_avatar_manager` | `DotAvatarManager` | `dot-platform` |
| `dot_auth_server` | `DotAuthServer` | `dot-server`、`dot-platform` |
| `dot_platform` | `DotPlatformHub` | `DotPlatformModule` |
| `dot_server`、`dot_console`、`dot_event_bus`、`dot_game_manager`、`dot_module_host`、`dot_admin_manager`、`dot_ban_manager`、`dot_chat_manager`、`dot_audit_log`、`dot_rcon_server`、`dot_query_server`、`dot_query_source`、`dot_a2s_server`、`dot_vote_manager` | `dot-server` | モジュール、そしてあなたのコード |
| `dot_client_link` | `DotClientLink` | ゲームのクライアント側コード |
| `dot_net_manager` | `DotNetManager` | 橋渡しコード |
| `dot_match`、`dot_combat`、`dot_loadout`、`dot_fps_controller`、`dot_screen_stack`、`dot_2d_arena`、`dot_2d_controller`、`dot_voice_manager`、`dot_voice_router`、`dot_moderation`、`dot_mod_tools`、`dot_vote_director` | それぞれのマネージャー | それを必要とするもの |

1 つのツリーに複数あって当然のマネージャーは `service_scope` を取り、2 つが
別々の名前で登録されるようになっています。

## フックまたは拒否できるサーバーイベント

`DotEventBus.hook_pre(name, callable)` はイベントの前に走り、**キャンセルできます**。
`hook_post` は後に走ります。フックは登録順に走り、キャンセルしたフックは残りの
事前フックを止めます。キャンセルされたイベントがハンドラーの半分だけ実行して
しまうべきではないからです。

| イベント | キャンセル可 |
| --- | --- |
| `server_start`、`server_shutdown` | 不可 |
| `client_connect`、`client_disconnect` | 不可 |
| `client_spawn` | 不可 |
| `client_kicked` | 不可 |
| `player_chat` | **可** |
| `player_command` | **可** |
| `game_changing` | **可** |
| `game_changed` | 不可 |
| `vote_started`、`vote_ended` | 不可 |
| `admin_action` | 不可 |

`declare(name, description)` で自分のイベントを登録すると、コンソールコマンド
`event_list` に現れます。モジュール作者がソースを読まずに、何にフックできるかを
知る方法です。

<Callout type="warning" title="`client_spawn` が持つのは `userid` であって `peer_id` ではありません">
セッションを `peer_id` で引くモジュールは毎回 null を得て、誰も追加しません。
しかも**無言で**です。null のセッションはそれ自体まったく正当な結果だからです。
これはこのコレクションの歴史で最も繰り返されたバグで、2 つの別々のゲームが
出荷し、どちらもエラーを出しませんでした。
</Callout>
