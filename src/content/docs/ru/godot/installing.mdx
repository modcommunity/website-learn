Все дополнения ставятся одинаково, и ответ намеренно скучный: **скопируйте
папку**.

## Установить дополнение

```bash
# dot-core нужен всему остальному. Копируйте его первым.
cp -r dot-core/addons/dot_core       моя-игра/addons/
cp -r dot-timer/addons/dot_timer     моя-игра/addons/
```

Затем включите каждое в *Проект → Настройки проекта → Плагины*.

<Callout type="info" title="Переключатель плагина лишь регистрирует типы для инспектора">
Все классы доступны через свой `class_name` независимо от того, включён плагин
или нет. Включение добавляет ресурсы в диалог *Создать ресурс*, а узлы — в
*Добавить узел*.
</Callout>

**Дистрибутив дополнения — это папка `addons/<имя>/` и больше ничего.** Всё
остальное в репозитории — `project.godot`, `examples/`, `fixtures/`,
`icon.svg` — существует, чтобы дополнение можно было открыть и проверить
отдельно, и в проект-потребитель не копируется.

## Требуется Godot 4.7 или новее

Коллекция создавалась на 4.4, а сейчас нацелена на **4.7.2**. Каждый
`project.godot` объявляет `config/features=PackedStringArray("4.7")`,
[`dotserve`](/learn/godot/tooling) и `setup.sh` серверного инструмента
отказываются работать со старшими версиями, а контейнер закрепляет
`4.7.2-stable` вместе с контрольной суммой.

Сам переход ничего не стоил в GDScript: ни одно задокументированное ломающее
изменение из 4.5, 4.6 и 4.7 — `JSONRPC.set_scope`, `Node.get_rpc_config`,
удалённые методы интерполяции `RenderingServer`,
`AudioEffectSpectrumAnalyzer.tap_back_pos`, сигнатуры OpenXR и
TextServerExtension — не встречается ни в одном из этих репозиториев.

## По репозиторию на ассет

**Каждый ассет — отдельный репозиторий Git и клонируется отдельно.**
Родительского репозитория нет, поэтому склонировать всю коллекцию разом
невозможно.

```bash
git clone https://github.com/modcommunity/dot-core
git clone https://github.com/modcommunity/dot-timer
```

Это следствие того, как их используют: тому, кому нужен таймер для спидранов,
должно хватить `dot-timer` и `dot-core` — и больше ничего.

## Локальная работа над дополнением

Каждому проекту, кроме `dot-core`, нужен присутствующий `dot-core` просто чтобы
*открыться*, а играм нужны все используемые ими дополнения. Эти ссылки внесены в
`.gitignore`, потому что потребитель вместо них копирует папки:

```bash
cd dot-cloud   # или любой проект дополнения
ln -s ../../dot-core/addons/dot_core addons/dot_core
```

```bash
cd game-arena
for pair in dot_core:dot-core dot_net:dot-net dot_server:dot-server \
            dot_fps_controller:dot-fps-controller dot_combat:dot-combat \
            dot_loadout:dot-loadout dot_match:dot-match dot_ui:dot-ui; do
  ln -s "../../${pair##*:}/addons/${pair%%:*}" "addons/${pair%%:*}"
done
```

[`dot-serve`](/learn/godot/tooling) не требует ничего из этого: это shell-скрипт,
который находит бинарник Godot во время работы.

## Двухшаговая проверка

Никакого CI нет. У каждого проекта одна и та же двухшаговая проверка, и **важны
оба шага**.

```bash
cd <проект>

# 1. Каждый скрипт разбирается.
godot --headless --path . --import
find . -name '*.gd' -not -path './.godot/*' | while read f; do
    godot --headless --path . --check-only --script "res://${f#./}"
done

# 2. Оно действительно работает.
godot --headless --path . res://examples/<пример>.tscn
```

<Callout type="warning" title="Проход --import не является необязательным">
Именно он регистрирует глобальные имена `class_name`. Без него каждая
межфайловая ссылка на тип рушится, и это выглядит как десятки не связанных
между собой ошибок — и **выполняйте его заново после добавления любого скрипта с
новым `class_name`**, иначе идентификатор не разрешится, сцена не загрузится, а
процесс *зависнет*, а не упадёт, потому что до `get_tree().quit()` дело не
дойдёт.
</Callout>

Шаг 2 — тот, который пропускают, и именно он что-то находит. Чисто
разбирающийся GDScript всё равно может быть неверным так, как показывает только
запуск: кэш интереса, отбрасывавший то, чем владел наблюдатель; шкала времени
отрисовки, не двигавшаяся между пакетами; `Dictionary`, выданный по ссылке, из-за
чего каждая «копия» делила один объект. Каждый пример-самопроверка при неудаче
завершается ненулевым кодом, поэтому годится как дымовой тест как есть.

<Callout type="info" title="Ограничивайте каждый безоконный запуск через `timeout`">
Сцена, скрипт которой не разбирается, зависает вместо падения — как и сцена
вообще без скрипта. Четыре примера сцен намеренно не являются самопроверками и
никогда не завершаются сами.
</Callout>

## Три цели, одна кодовая база

Настольные системы (Windows, macOS, Linux), мобильные (Android, iOS) и браузер.
Ограничения живут в браузере, и они закодированы в самом коде, а не оставлены на
усмотрение читателя — см.
[Соглашения](/learn/godot/conventions#the-browser-decides-half-of-this).

Самый быстрый способ узнать, что сборка действительно умеет:

```bash
godot --headless --path . res://examples/capability_report.tscn
```

Запускайте его на каждой платформе, куда выпускаете. Именно так выясняется, что
у веб-сборки нет потоков или что устройство не сообщает квоту хранилища — и то и
другое меняет поведение [`dot-cloud`](/learn/godot/addons/dot-cloud).
