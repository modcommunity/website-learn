**Ничто в коллекции не должно требовать форка.** Изменение, из-за которого до
любой из перечисленных ниже точек станет труднее добраться, считается
регрессией, даже если все тесты по-прежнему проходят.

Точек расширения пять видов, и понимание того, с каким видом вы имеете дело,
подсказывает, где его искать.

<Params>
  <Param name="Унаследовать базовый класс">
    Абстрактный класс с задокументированным набором методов с префиксом `_`,
    которые нужно переопределить. Хранилища, источники, кодеки, правила, экраны,
    модули. Всего около тридцати.
  </Param>
  <Param name="Присвоить Callable">
    Поле на узле, обычно с именем `*_fn` или `*_source`, отвечающее на
    единственный вопрос, на который дополнение намеренно не может ответить само:
    где находится игрок, в какой он команде, куда уходят байты. Около
    пятидесяти.
  </Param>
  <Param name="Создать Resource">
    Файл `.tres`, который дизайнер редактирует в инспекторе: параметры движения,
    схемы, каталоги, правила, стили, поверхности. Вообще без кода.
  </Param>
  <Param name="Опубликовать под именем в реестре">
    Швы на утиной типизации. Зарегистрируйте объект с одним методом под
    согласованным именем — и два дополнения сотрудничают, не импортируя друг
    друга.
  </Param>
  <Param name="Наслоить настройку">
    Любой `DotConfig`: экспортированные значения по умолчанию, затем файл JSON
    или YAML, затем окружение, затем командная строка.
  </Param>
</Params>

## Полный указатель

| Что изменить | Где |
| --- | --- |
| К какому узлу цепляется компонент | `DotNodeRef` у каждого компонента |
| Источники контента (CDN, диск, внутриканальный) | наследник `DotCloudSource` |
| Как игрок проходит аутентификацию (Steam, Epic, свой вариант) | наследник `DotAuthProvider`, `DotAuthServer.add_provider` |
| Где хранятся баны (общая БД, HTTP-служба) | наследник `DotBanStore` у `DotBanManager` |
| Группы сайта → права на сервере | `DotAuthAdminSource` или любой объект с `lookup()` / `source_name()` |
| Команды и поведение сервера | наследник `DotModule` либо `DotConsole.command` |
| Что запрос к серверу сообщает об игре | `DotQueryProvider` либо `DotModule.add_query_provider` |
| Отреагировать на что-то или запретить это | `DotEventBus.hook_pre` / `hook_post` |
| Что реплицируется и с какой точностью | объявления `DotNetVar`; `Type.CUSTOM` для любого типа |
| Симуляция, управление, сообщения | наследники `DotNetBehaviour`, `DotNetInput`, `DotNetMessage` |
| Кто что видит | наследник `DotNetInterest` |
| Как создаются сущности | `DotNetSpawner.register_factory` |
| Куда уходят байты | `DotNetManager.send_fn`, наследник `DotTransport` |
| Откуда берётся и куда идёт голос | наследник `DotVoiceSource` / `DotVoiceSink` |
| Голосовой кодек | наследник `DotVoiceCodec`, `DotVoiceCodec.register` |
| Кто кого слышит в голосе | `DotVoiceRouter.team_fn` / `position_fn` / `listener_filter` |
| Кому вообще позволено говорить | всё, у чего есть `is_voice_muted(peer)`, под `dot_mute_source` |
| Где живут наказания | наследник `DotPunishmentStore` |
| Какая база данных их хранит | наследник `DotSqlDriver` либо `DotPunishmentStoreRest` |
| Как узел соответствует человеку | `DotModerationManager.key_for_peer` |
| Чей список банов применяет сервер | всё, что зарегистрировано как `dot_ban_source` |
| Сколько клиентов может держать один адрес | `sv_max_connections_per_ip`, `DotAddressGuard` |
| Как модератор называет игрока | `DotServer.find_sessions` — имя, логин, id, `ip:`, `@me` |
| Где игрок и как его переместить | `DotModTools.position_fn` / `teleport_fn` |
| Что происходит при входе игрока | `DotPlatformModule` либо `DotPlatformHub.admit` напрямую |
| Откуда берутся права на предметы | `DotPlatformHub.entitlement_source` |
| Где живут профили | наследник `DotUserStore` у `DotUserManager` |
| Каким может быть имя | `DotUserManager.name_filter` |
| Что игрок может носить | `DotAvatarSchema` + `DotAvatarEntitlements` |
| Где живут аватары | наследник `DotAvatarStore` |
| Как id детали превращается в ассет | `DotAvatarCatalogue.resolver` |
| Ощущение движения | `DotFpsTunables`, на экземпляр или через файл JSON |
| Именованная вариация — боком, низкая гравитация, prebhop | `DotFpsStyle` + `DotTimerStyle`, связанные по id |
| Как ведёт себя один вид покрытия | `DotFpsSurface` внутри `DotFpsSurfaceSet` |
| Временное изменение — ускоритель, оглушение, катапульта | `DotFpsModifier` |
| Совершенно новый способ движения — лестница, вода, крюк | наследник `DotFpsMoveMode` |
| С чем сталкивается игрок | наследник `DotFpsBody` через `DotFpsController._make_body` |
| Устройства ввода, боты, воспроизведение демо | `DotFpsSampler` / `Dot2DSampler` либо соберите команду сами |
| На что таймер реагирует в мире | `DotTimerZone.Kind`, нарисованное в редакторе или через `DotTimerZonePainter` |
| Где живут рекорды и таблицы | наследник `DotTimerStore` / `DotLeaderboardStore` |
| Что такое карта и что играется дальше | `DotMapDef` в каталоге; `DotMapRotation`, `DotMapVote` |
| Как смена карты доходит до клиентов | `DotMapSyncHost.send_fn` / `DotMapSyncClient.send_fn` |
| Что клиент загрузит по слову хоста | `DotMapSyncClient.accept_unknown_maps` |
| Любая политика голосования | `DotVoteRules`, 55 настроек, слоистых как любой `DotConfig` |
| За что можно голосовать и что значит «играем это» | наследник `DotVoteSource` либо `DotVoteGameSource` / `DotVoteMapSource` / `DotVoteListSource` |
| Кто считается игроком, админом или зрителем в голосовании | `DotVoteDirector.player_count_fn` / `is_admin_fn` / `is_spectator_fn` |
| Сколько весит голос одного игрока | `DotVoteDirector.weight_fn` |
| Как называются команды голосования | `DotVoteCommands.prefix` / `names` |
| Что можно создавать и сколько | `DotPropCatalogue`, `DotPropLimits` |
| Новый инструмент песочницы или оружие | наследник `DotPropTool` |
| Объект с собственным кодом | `DotPropDef.meta.script`, ПУТЬ |
| Что такое оружие | `DotWeapon`, и `DotDamageType` для того, как оно ранит |
| Куда летит выстрел | наследник `DotTrace` — `DotTracePhysics` или `DotTraceFlat` |
| Именованные зоны тела и их множители | `DotHitGroup`, таблица, а не перечисление |
| Огонь по своим, урон себе, ограничения | `DotDamageRules` плюс `DotDamageResolver.adjust` |
| Включить компенсацию задержки | `DotCombatManager.rewind_fn` / `restore_fn`, два callable |
| Что такое предмет и что куда подходит | `DotItem`, `DotLoadoutSlot`, `DotLoadoutSchema` |
| Где живут наборы снаряжения | наследник `DotLoadoutStore` |
| Что значит победить | наследник `DotMatchRules` — `_round_outcome`, `_round_winner` |
| Где появляются игроки | `DotSpawnPoint`, `DotSpawnSelector.danger_fn` / `filter_fn` |
| Что такое экран | наследник `DotScreen`, зарегистрированный в `DotScreenStack` |
| Как выглядит интерфейс | `Theme` либо палитра `DotUiTheme`. `dot-ui` не поставляет графику |
| Как строится экран настроек | Никак: `DotSettingsPanel` читает ваш `DotConfig` |
| Как двигается объект в 2D | `Dot2DTunables`, и `Dot2DMassRules` для игры на массе |
| С чем сталкивается объект в 2D | наследник `Dot2DBody` |
| Долгая работа без блокировки кадра | наследник `DotJob` на `DotScheduler` |
| Куда уходят записи журнала | `DotLogSink` либо `DotLog.add_sink` с `Callable` |

## Точки наследования по дополнениям

Каждая из них — абстрактная база с небольшим задокументированным набором
методов. Помеченные словом **обязателен** не имеют полезного значения по
умолчанию.

<Params>
  <Param name="DotTransport" type="dot-core">
    **`_create_server`**, **`_create_client`**, `_transport_name`,
    `_is_available`, `supports_web_clients`, `scheme`. `_is_available`
    проверяется до использования, так что отказ звучит как «эта сборка не может
    держать сервер по ENet» на старте, а не как нулевой peer тремя вызовами
    позже.
  </Param>
  <Param name="DotJob" type="dot-core">
    **`_step`** (ограниченный кусок работы; true, если осталось ещё),
    `_progress` (0..1 или **-1**, когда объём действительно неизвестен —
    честная неопределённая полоса лучше прыгающей назад), `_setup`,
    `_teardown`, `is_thread_safe`.
  </Param>
  <Param name="DotConfig" type="dot-core">
    `env_prefix`, `cli_prefix`, `sensitive_keys`, `validate`.
  </Param>
  <Param name="DotLogSink" type="dot-core">
    Обработчик записей журнала. `DotLog.add_sink(callable)` — однострочный
    вариант.
  </Param>
  <Param name="DotCloudSource" type="dot-cloud">
    `source_name`, `is_supported`, `can_serve(manifest)`, **`fetch`**. `fetch`
    обязан писать в `DotCloudStore.partial_path`, по возможности продолжать с
    `partial_size` и завершать через `commit_partial` — единственное место, где
    проверяется хеш. Писать прямо в каталог объектов — ровно тот путь, которым
    непроверенный контент оказывается смонтированным.
  </Param>
  <Param name="DotAuthProvider" type="dot-auth">
    `_provider_name`, **`_handles(credential)`** (дёшево и чисто структурно),
    **`_authenticate(credential)`**, `_validate`. Провайдер, который взял
    учётные данные и затем их отверг, уже принял решение: сервер *не* переходит
    к следующему.
  </Param>
  <Param name="DotNetBehaviour" type="dot-net">
    `_register_net_vars`, `_net_ready`, `_net_removed`, `_net_simulate`,
    `_net_state_applied`, `_net_interpolated`, `_net_read_property`,
    `_net_write_property`. Класс, который игра наследует чаще всего.
  </Param>
  <Param name="DotNetInput" type="dot-net">
    **`_write`**, **`_read`**, `_sanitise` (ограничивает всё, что клиент мог бы
    преувеличить: квантование уже ограничивает каждое поле по отдельности, здесь
    речь о *связях* между ними), `_equals` для подавления избыточности.
  </Param>
  <Param name="DotNetMessage" type="dot-net">
    **`_type_name`** (с пространством имён; ваше не должно начинаться с `net.`),
    **`_write`**, **`_read`**, `_validate`. Проверяйте в `_validate`, а не в
    обработчике: обработчик, который проверяет, — это обработчик, который
    кто-нибудь скопирует без проверки.
  </Param>
  <Param name="DotNetInterest" type="dot-net">
    `_is_relevant` (для большинства стратегий переопределяют только его),
    `_candidates` для пакетного фильтра, `_prepare` для перестроения индекса раз
    на снимок, `_score` для приоритизации при жёстком бюджете.
  </Param>
  <Param name="DotModule" type="dot-server">
    **`_module_name`**, `_module_version`, `_module_description`,
    `_module_author`, **`_module_load`**, `_module_unload`,
    `_module_game_changed`. Команды, cvar-ы и хуки, зарегистрированные через
    помощники, откатываются автоматически; переопределяйте `_module_unload` ради
    таймеров, файлов и сокетов.
  </Param>
  <Param name="DotBanStore" type="dot-server">
    `_store_name`, **`_load`**, `_put`, `_remove`, `_refresh`, `_writable`.
  </Param>
  <Param name="DotQueryProvider" type="dot-server">
    `_provider_name`, **`_contribute(snapshot)`** — так игра публикует
    собственное состояние в ответе на запрос к серверу.
  </Param>
  <Param name="DotUserStore / DotAvatarStore / DotLoadoutStore" type="dot-user, dot-user-avatar, dot-loadout">
    Во всех трёх одна и та же форма: **`_fetch`**, `_store`, `_remove`, `_open`,
    `_close`, `_writable`, `_store_name`. Успешный **null** означает «у этого
    игрока их нет», и это не ошибка.
  </Param>
  <Param name="DotPunishmentStore" type="dot-moderation">
    `store_name`, `is_writable`, **`load_all`**, `put`, `update`, `remove`. В
    паре с `DotSqlDriver` (`dialect`, `open`, `execute`, `query`, `batch`),
    когда бэкенд — база данных.
  </Param>
  <Param name="DotTimerStore / DotLeaderboardStore" type="dot-timer, dot-leaderboard">
    `put`, `top` / `page`, `best_for` / `entry_for`, `rank_of`, `count_on`,
    `remove`. Менеджер сортирует; хранилищу это делать не обязательно.
  </Param>
  <Param name="DotMatchRules" type="dot-match">
    `_points_for_kill`, **`_round_outcome`**, `_round_winner`, `_respawn_delay`.
    `DotRulesElimination` — разобранный пример того, зачем это нужно.
  </Param>
  <Param name="DotTrace" type="dot-combat">
    **`_world_ray`** и больше ничего. Обход хитбоксов, разрешение ничьей в пользу
    стены и восстановление принадлежат базовому классу.
  </Param>
  <Param name="DotFpsBody / Dot2DBody" type="dot-fps-controller, dot-2d">
    `sweep` / `move`, `overlaps`, `describe`. Запросы столкновений, нужные

  </Param>

    `_name`, `_enter`, `_exit`, **`_simulate`**, `_uses_crouch`. Лестница, вода,

    отказывается закрываться, — это экран, в котором игрока можно запереть.
  </Param>

## Зацепки-Callable

Дополнение умеет делать работу; чего оно не знает — так это вашего мира. Вот
вопросы, угадывать ответы на которые оно отказывается, сгруппированные по смыслу.

**Куда уходят байты.** `DotNetManager.send_fn`, `DotVoiceManager.send_fn`,
`DotVoiceRouter.send_fn`, `DotMapSyncHost.send_fn`, `DotMapSyncClient.send_fn`.
Ни одно из этих дополнений не владеет сокетом — поэтому `dot-net` работает и
через петлю, и через настоящий транспорт, и через ваш собственный.

**Где что находится.** `DotMatch.position_fn`, `DotVoiceRouter.position_fn`,
`DotModTools.position_fn` / `teleport_fn`. `DotModTools` намеренно принимает
позиции типа `Variant`, так что 2D — полноправный сценарий, а не то, что
приходится обходить.

**Кто кем считается.** `DotDamageResolver.team_of`,
`DotVoiceRouter.team_fn` / `listener_filter`,
`DotVoteDirector.player_count_fn` / `is_admin_fn` / `is_spectator_fn` /
`voters_fn` / `weight_fn`, `DotRulesElimination.alive_fn`,
`DotModerationManager.key_for_peer`, `DotModTools.immunity_fn`.

**Что игрок имеет и как он может называться.**
`DotLoadoutManager.entitlement_source`, `DotPlatformHub.entitlement_source`,
`DotUserManager.name_filter`, `DotItemCatalogue.resolver`,
`DotAvatarCatalogue.resolver`.

**Насколько отматывается выстрел.** `DotCombatManager.rewind_fn` /
`restore_fn`. Две строки включают компенсацию задержки; без них выстрелы
разрешаются относительно настоящего момента — что верно для listen-сервера и
неверно для всех, у кого есть задержка.

**Всё остальное.** `DotSpawnSelector.danger_fn` / `filter_fn`,
`DotDamageResolver.adjust`, `DotFpsMotor.surface_resolver`,
`DotPickupField.wants_fn` / `tags_fn`, `DotHudWidget.source`,
`DotStatBar.max_source`, `DotConVar.validator`, `DotConCommand.completer`,
`DotBackboneClient.roster_provider` / `stats_provider`,
`DotVoteDirector.announce_fn`, `DotVoteListSource.apply_fn`,
`DotVoiceManager.sink_factory`, `DotNetVar.read_fn` / `write_fn` /
`change_handler`, `DotNetSpawner.register_factory`.

<Callout type="warning" title="Неприсвоенная зацепка — это не ошибка">
Почти у каждой из них есть разумное поведение «по умолчанию», и именно поэтому
забытую так трудно найти: неподключённый `entitlement_source` означает, что у
игрока ничего нет; неприсвоенный `rewind_fn` означает отсутствие компенсации
задержки; неприсвоенный `key_for_peer` означает, что наказания привязаны не к
тому. `describe_lines()` каждого дополнения сообщает, чего ему не хватает —
прочтите это прежде, чем решить, что функция сломана.
</Callout>

## Ресурсы, которые вы создаёте

Ни кода, ни наследования — `.tres` или файл JSON.

| Ресурс | Что он определяет |
| --- | --- |
| `DotFpsTunables` | Все числа движения. Слоями: значения по умолчанию < JSON < `DOT_FPS_*` < `--fps-*` |
| `DotFpsSurface` / `DotFpsSurfaceSet` | Лёд, грязь, конвейер. **Множители, никогда не абсолютные значения**, чтобы перенастройка базового ощущения передавалась дальше |
| `DotFpsModifier` | Временное изменение: ускоритель, зона замедления, оглушение, катапульта |
| `DotFpsStyle` | Именованная вариация — боком, спиной, низкая гравитация, prebhop |
| `Dot2DTunables` / `Dot2DMassRules` | Вид сверху, тяга или blob; и как масса превращается в размер, скорость и право кого-то съесть |
| `DotWeapon` / `DotDamageType` / `DotHitGroup` | Что такое оружие, как оно ранит и сколько стоит выстрел в голову |
| `DotDamageRules` | Огонь по своим, урон себе, спад с дистанцией, ограничения — в одном порядке, один раз |
| `DotItem` / `DotLoadoutSlot` / `DotLoadoutSchema` | Правила снаряжения игрового режима |
| `DotAvatarSchema` / `DotAvatarSlot` / `DotAvatarPart` | Какие детали существуют и какие значения допустимы |
| `DotMatchRules` | Что значит победить и сколько стоит убийство |
| `DotSpawnPoint` / `DotTeam` | Где появляются игроки и на чьей они стороне |
| `DotTimerZone` / `DotTimerZoneSet` / `DotTimerStyle` | На что реагирует таймер и что такое зачётный стиль |
| `DotMapDef` в JSON-каталоге | Карта: id, версия, сцена и, возможно, пакет контента |
| `DotPropDef` / `DotPropCatalogue` / `DotPropLimits` | Что можно создавать и сколько |
| `DotVoteRules` | Пятьдесят пять настроек — от метода подсчёта до разрешения ничьей |
| `DotLeaderboardDef` / `DotStatsSchema` | По чему упорядочивается таблица и как новое значение встречается со старым |
| `DotUiTheme` | Целая `Theme` из палитры и масштаба. Без графических ассетов |

## Швы в реестре

Опубликуйте объект под одним из этих имён — и что-то другое его найдёт, причём
ни одна из сторон не импортирует другую.

| Имя | Кто публикует | Кто спрашивает |
| --- | --- | --- |
| `dot_ban_source` | `DotModerationManager` | проверка допуска в `dot-server` |
| `dot_mute_source` | `DotModerationManager` | `DotVoiceRouter` |
| `dot_cloud_client` | `DotCloudClient` | загрузчик `dot-map`, смена игры в `dot-server`, каталог `dot-user-avatar` |
| `dot_user_manager` | `DotUserManager` | `dot-server`, `dot-platform` |
| `dot_avatar_manager` | `DotAvatarManager` | `dot-platform` |
| `dot_auth_server` | `DotAuthServer` | `dot-server`, `dot-platform` |
| `dot_platform` | `DotPlatformHub` | `DotPlatformModule` |
| `dot_server`, `dot_console`, `dot_event_bus`, `dot_game_manager`, `dot_module_host`, `dot_admin_manager`, `dot_ban_manager`, `dot_chat_manager`, `dot_audit_log`, `dot_rcon_server`, `dot_query_server`, `dot_query_source`, `dot_a2s_server`, `dot_vote_manager` | `dot-server` | модули и ваш собственный код |
| `dot_client_link` | `DotClientLink` | клиентский код игры |
| `dot_net_manager` | `DotNetManager` | мосты |
| `dot_match`, `dot_combat`, `dot_loadout`, `dot_fps_controller`, `dot_screen_stack`, `dot_2d_arena`, `dot_2d_controller`, `dot_voice_manager`, `dot_voice_router`, `dot_moderation`, `dot_mod_tools`, `dot_vote_director` | их собственные менеджеры | всё, чему они нужны |

Менеджеры, которых законно может быть больше одного в дереве, принимают
`service_scope`, чтобы двое из них регистрировались под разными именами.

## Серверные события, которые можно перехватить или запретить

`DotEventBus.hook_pre(name, callable)` выполняется до события и **может его
отменить**; `hook_post` — после. Хуки выполняются в порядке регистрации, и хук,
который отменяет событие, останавливает остальные предварительные хуки:
отменённое событие не должно исполнить половину своих обработчиков.

| Событие | Отменяемое |
| --- | --- |
| `server_start`, `server_shutdown` | нет |
| `client_connect`, `client_disconnect` | нет |
| `client_spawn` | нет |
| `client_kicked` | нет |
| `player_chat` | **да** |
| `player_command` | **да** |
| `game_changing` | **да** |
| `game_changed` | нет |
| `vote_started`, `vote_ended` | нет |
| `admin_action` | нет |

`declare(name, description)` регистрирует ваши собственные — именно это выводит
их в консольной команде `event_list`, и именно так автор модуля узнаёт, к чему
можно подцепиться, не читая исходники.

<Callout type="warning" title="`client_spawn` несёт `userid`, а не `peer_id`">
Модуль, ищущий сессию по `peer_id`, каждый раз получает null и никого не
добавляет — **молча**, потому что пустая сессия сама по себе законный результат.
Это самая повторяющаяся ошибка в истории коллекции: две разные игры выпустили её,
и ни одна не выдала ошибки.
</Callout>
