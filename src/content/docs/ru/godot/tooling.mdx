[`dot-server`](/learn/godot/addons/dot-server) настраивается очень глубоко:
cvar-ы, флаги, `server.cfg`, `autoexec.cfg`, аргументы `+command`, RCON и
слоистая конфигурация из файла, окружения и argv. Чего у него не было — так это
входной двери. Вот дверной звонок.

## `dotserve`

Единственная часть коллекции, которая не является дополнением Godot: shell-скрипт,
которому нужны `bash` и бинарник Godot 4.7+.

```bash
./install.sh                 # ставит ссылки в ~/.local/bin
sudo ./install.sh --prefix /usr/local/bin
```

```bash
dotserve                            # разумные значения и адрес для подключения
dotserve --game res://games/arena   # конкретная игра
dotserve --port 27015 --web         # слушать ещё и браузерных клиентов
dotserve --restart                  # подниматься после падения
dotserve -- +sv_cheats 1 +map dm_arena
```

Первый запуск пишет прокомментированный `server.cfg` в `~/.config/dotserve`,
генерирует пароль RCON и печатает его один раз. Каждый следующий запуск читает
файл и никогда его не трогает.

### То, что легко забыть сделать

**Он печатает адрес, который можно отправить другу**, включая адрес в локальной
сети — потому что «пишет, что запустился, а друг подключиться не может» почти
всегда означает адрес привязки или брандмауэр, и первое, что помогает, — знать,
на каком адресе сервер на самом деле.

**Он отказывается стартовать с угадываемым паролем RCON.** Пустой пароль
допустим и означает, что слушатель RCON просто не открывается. Отвергается
шаблонная заглушка, которую поставили вместе с релизом, скопировали с форума или
оставили в образце.

**Пароль RCON никогда не попадает в командную строку.** `server.cfg` создаётся с
правами 600 прежде, чем туда что-либо запишут. argv и окружение читаются любым
другим процессом на машине, и оба попадают во вставленные отчёты об ошибках — по
той же причине их отвергает `DotConfig.sensitive_keys`.

**Он никогда не перезаписывает ваш `server.cfg`.** Ваши правки *и есть*
конфигурация сервера.

### Опции, которые стоит знать

| | |
| --- | --- |
| `--dry-run` | Печатает команду, которую запустил бы, и выходит. |
| `--print-config` | Печатает итоговую конфигурацию и выходит. |
| `--install-service [ИМЯ]` | Печатает unit systemd для этого запуска. |
| `--restart` | Перезапуск после падения, с экспоненциальной задержкой до 60 секунд. |
| `--web` | Слушать ещё и браузерных клиентов по WebSocket на самом игровом порту (TCP рядом с UDP родных клиентов). `--ws-port` принимается из старых unit-файлов и игнорируется. |

Коды выхода осмысленные, чтобы супервизор отличал ошибку конфигурации от падения:
`2` — неверное использование, `3` — нет Godot, `4` — нет проекта, `5` — плохая
конфигурация, `6` — порт занят. Сгенерированный unit systemd перечисляет коды с `3` по `6` в
`RestartPreventExitStatus`.

## Серверный инструмент TMC

`dot-server-deploy` — место, где коллекция собирается в то, что владелец
сервера запускает одной командой. Это проект Godot, который поднимает
`dot-server`, читает конфигурацию из `cfg/*.yml`, загружает игры из `content/` и
отдаёт браузерный клиент — и **собственной игры не содержит**. Каждая игра, включая лобби, — это подписанный пакет [dot-cloud](/learn/godot/addons/dot-cloud), который сервер устанавливает из источника содержимого, а каждый клиент скачивает при подключении, так что клиент — одна и та же сборка независимо от того, к чему он присоединяется, а новой игре не нужна новая.

```bash
./setup.sh              # найти рантайм, подключить дополнения, написать ./server
./server                # запустить

docker compose up -d    # или то же самое в контейнере
```

Windows: `setup.bat` (обёртка над `setup.ps1`), затем `.\server.ps1`.

<Callout type="info" title="Раньше он назывался `dot-server-setup-test`">
Тот же проект, название яснее. Если у вас старая копия или старая ссылка, теперь
это [`modcommunity/dot-server-deploy`](https://github.com/modcommunity/dot-server-deploy).
</Callout>

### Три скрипта, которые легко перепутать

```bash
./play.sh               # сервер и браузерный клиент на loopback
./play.sh playground    # начать с конкретной игры
./play.sh games         # что ещё лежит в content/
./play.sh status
./play.sh down
```

`play.sh` — для разработчика, который изменил строку и хочет на неё посмотреть. Он
печатает ссылку, пересобирает экспорт, когда тот устарел, копирует `embed.html` — страницу, которая берёт `?server=` из строки запроса, — в сборку рядом со сгенерированным Godot `index.html` и **сообщает, когда опубликованный пакет в `dist/` старше репозитория
игры, из которого он собран**. Дополнения подключены симлинками и всегда свежие;
пакет — это снимок, поэтому он единственный, что устаревает, а устаревший пакет
монтируется без ошибок, запускается — и это игра недельной давности.

`demo.sh` — другой: пять серверов, nginx, терминирующий TLS, публичный хост,
отдельный регистрируемый домен для игры и шаг с `sudo`, чтобы установить
слушатель. Подходит, чтобы показать платформу кому-то, и не подходит для правки в
одну строку.

К `dev.sh` ни тот ни другой отношения не имеют: он запускает **сайт** и не
запускает никакой игры. Они работают бок о бок.

<Callout type="warning" title="`play.sh` — только loopback по HTTP">
HTTPS-страница не может открыть сокет `ws://`, поэтому такая форма работает здесь
и больше нигде. Вставка игры *внутрь* сайта — это уже совсем другое дело, и ей
нужен собственный регистрируемый домен.
</Callout>

### Что он даёт оператору

- **Одна команда для запуска.** `setup.sh` находит рантайм Godot, подключает
  дополнения, пишет прокомментированный `cfg/` и создаёт `./server`. Уже
  существующий файл конфигурации не перезаписывается никогда. RCON поставляется
  включённым, со сгенерированным паролем и только через loopback.
- **Конфигурация в YAML**, разбитая по темам: `server.yml`, `net.yml`,
  `rcon.yml`, `auth.yml`, `groups.yml`, `permissions.yml`, `vote.yml`, `content.yml`, `security.yml`, `log.yml`, `replay.yml`, `party.yml`, `matchmaking.yml`, `admin_menu.yml`, `loading.yml`. Всё, что
  `dot-server` выставляет как консольную переменную, может попасть туда под своим
  именем.
- **Роли, а не флаги.** Модель прав в dot-server намеренно состоит из флагов;
  `groups.yml` — это перевод, так что оператор пишет
  `permissions: [kick, ban, mute]` в группе `admin`, а игрок получает флаги.
- **Игры устанавливаются по имени.** `--games g2gfast,playground` (или `TMC_GAMES`) при запуске скачивает дескриптор и пакет каждой игры из источника содержимого; `owner/name@version` называет опубликованную кем-то другим игру. Каталог внутри `content/` с файлом `game.yml` — это игра, а `changelevel` переключает между ними, не разрывая подключений.
- **Игроки выбирают следующую игру.** `!game_nominate`, `!game_rtv`, `!game_vote`, `!game_timeleft`, `!game_next` по играм из `content/`, через [`dot-vote`](/learn/godot/addons/dot-vote). Префикс оставляет голый `!rtv` игре, которая голосует за собственные карты. У каждой игры собственный лимит времени в собственном `game.yml`.
- **Браузерный клиент.** `./server export-web` собирает его; одной сборки хватает
  на любой сервер, потому что адрес берётся из `?server=`.

### Раскладка и почему она делится натрое

```
cfg/       то, что правит оператор
content/   игры, которые он предлагает — по одному game.yml; сама игра — пакет
data/      то, что сервер пишет — from_yaml.cfg, admins.json, bans.json, audit.jsonl, кэш пакетов
dist/      пакеты, опубликованные с этой машины, и индекс, из которого устанавливают серверы
host/      загрузка: YAML -> DotServer
client/    оболочка клиента. Игры не содержит; монтирует то, что назовёт сервер
web/       браузерная сборка и страница, читающая ?server= из URL
```

`cfg/` правите вы, а `data/` пишет сервер. `content/` пишется, когда сервер устанавливает игру, потому что `game.yml` извлекается из подписанного пакета; машина, которая несёт собственное содержимое и ничего не устанавливает, может смонтировать его только для чтения.

<Callout type="info" title="`data/from_yaml.cfg` — это то, во что превратился ваш YAML">
Читайте его, когда кажется, что настройка игнорируется. YAML здесь — это
**поверхность над собственным словарём dot-server**, а не второй словарь, и этот
файл и есть перевод.
</Callout>

Это ещё и то место, где каждая игра коллекции публикуется как пакет и переключается под подключёнными игроками, и первое место, где что-либо из этой коллекции вообще было загружено в браузере.
