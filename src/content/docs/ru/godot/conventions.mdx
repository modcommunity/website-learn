Эти правила действуют в каждом дополнении. Нарушить одно — значит сломать
совместимость сразу в двадцати двух репозиториях, так что их стоит знать до
того, как писать код против любого из них.

## `DotRegistry` вместо автозагрузок

**Ни одно дополнение нигде не поставляет автозагрузку.**

Автозагрузка занимает глобальный идентификатор в каждом проекте-потребителе,
фиксирует порядок инициализации и не может быть создана дважды — а это исключает
запуск сервера и клиента в одном процессе или двух серверов в одной сессии
редактора. Эта коллекция делает и то и другое постоянно.

Поэтому компоненты — это `Node`, которые вы размещаете сами, а находят они друг
друга по имени:

```gdscript
DotRegistry.register(&"dot_server", self)

var cloud: Object = DotRegistry.get_service(&"dot_cloud_client")
if cloud != null:
    ...
```

Большинство менеджеров регистрируются в `_enter_tree` и снимают регистрацию в
`_exit_tree`, под константой `SERVICE`, с флагом `register_service` и с
`service_scope` на случай, когда в одном дереве нужны два экземпляра.

Статические классы не могут объявлять сигналы — поэтому рядом с `DotLog` и
`DotRegistry` существуют `DotLogBus` и `DotRegistryBus`.

### Имена в реестре, которые являются швами

Три из них — это *контракты*, а не просто поиск: одно имя, один метод, и ни одно
дополнение не называет другое:

<Params>
  <Param name="dot_ban_source">
    Всё, у чего есть `check_admission(uid, address) -> DotResult`.
    [`dot-server`](/learn/godot/addons/dot-server) спрашивает это при каждом
    подключении; [`dot-moderation`](/learn/godot/addons/dot-moderation)
    публикуется под этим именем.
  </Param>
  <Param name="dot_mute_source">
    Всё, у чего есть `is_voice_muted(peer) -> bool`. Маршрутизатор
    [`dot-voice`](/learn/godot/addons/dot-voice) сверяется с ним перед
    ретрансляцией кадра.
  </Param>
  <Param name="dot_cloud_client">
    Всё, что понимает `ensure(content_id, version)` /
    `is_mounted(content_id, version)`. Загрузчик
    [`dot-map`](/learn/godot/addons/dot-map) и смена игры в
    [`dot-server`](/learn/godot/addons/dot-server) обращаются к контенту через
    него.
  </Param>
</Params>

Полный список имён служб — на странице [точек
расширения](/learn/godot/extending#registry-seams).

## Ничто не прописывает путь к сцене жёстко

Любой компонент, которому нужен узел из проекта-хозяина, экспортирует
**`DotNodeRef`** — редактируемое в инспекторе описание того, *какой это узел*:
относительный, абсолютный, сам объект, родитель, группа, служба реестра,
ближайший предок или потомок нужного типа, либо «создать узел, если его нет».

```gdscript
session.world_ref = DotNodeRef.of_path(^"../World")
spawner.world_ref = DotNodeRef.of_group(&"world_root")
```

Решает хозяин, для каждого экземпляра, в инспекторе. Дополнение, жёстко
прописавшее `$"../../World"`, — это дополнение, чью структуру сцены пришлось бы
принять целиком.

<Callout type="warning" title="`of_self()` разрешается в узел, на котором стоит ссылка">
На контроллере это означает сам *контроллер*, а не тело персонажа под ним —
которое является обычным `Node`, так что `setup()` отказывает, и игрок никогда не
симулируется. Это стоило девяти провалов в одном наборе тестов, и ни один из них
не указывал на ссылку.
</Callout>

## `DotResult` для всего, что может не получиться

Никогда null, никогда пара в `Array`, никогда голый `false`.

```gdscript
var res := await manager.resolve(identity)
if not res.ok:
    if res.error.code == DotError.CODE_RATE_LIMITED:
        wait(res.error.retry_after)
    return
var profile: DotUserProfile = res.value
```

Вызывающая сторона ветвится по `DotError.CODE_*`, **никогда по тексту
сообщения**: коды стабильны, а сообщения — для людей. `res.wrap(...)` добавляет
контекст, не теряя причину, а чтение `.value` у неудачи вызывает ошибку, а не
возвращает правдоподобное значение по умолчанию.

## Конфигурация слоистая, одинаково везде

```
экспортированные значения по умолчанию  <  файл JSON  <  окружение  <  командная строка
```

Любой наследник `DotConfig` просто объявляет свойства `@export`; обнаружение
рефлексивное, так что новая настройка не требует кода разбора. Форму ей задают
четыре зацепки:

<Params>
  <Param name="env_prefix()" type="String">
    например `"DOT_SERVER_"`. Верните `""`, чтобы полностью отключить
    переопределение из окружения — это правильно для конфигурации, описывающей
    *контент*, а не развёртывание, где переменная окружения, меняющая поведение,
    была бы неожиданностью.
  </Param>
  <Param name="cli_prefix()" type="String">
    например `"--sv-"`.
  </Param>
  <Param name="sensitive_keys()" type="PackedStringArray">
    Свойства, которые ни в коем случае нельзя задавать из окружения или командной
    строки. И то и другое на большинстве систем читается другими процессами, и то
    и другое попадает в вывод `ps` и во вставленные в тикет отчёты об ошибках.
  </Param>
  <Param name="validate()" type="DotResult">
    Ловит то, чего не поймает рефлексия: порт вне 1–65535, нулевой тикрейт, URL
    без схемы. Вызывается из `load_layered()`.
  </Param>
</Params>

Тот же `sensitive_keys()` не даёт
[`DotSettingsPanel`](/learn/godot/addons/dot-ui) вывести секрет на экран.

## `describe()` у всего, что имеет состояние

Каждый компонент с состоянием отвечает на `describe()` / `describe_lines()`,
чтобы консольная команда или отчёт об ошибке могли его выгрузить. Там же
дополнение сообщает, чего оно *не может* в текущей конфигурации:
`dot-moderation` пишет, что ничего не зарегистрировано как `dot_ban_source`, то
есть бан — это строка в файле, которая никого не останавливает, — и пишет это там,
куда смотрит оператор.

## У всего префикс `Dot`

`class_name` в Godot глобален, а эти дополнения ставятся бок о бок, поэтому у
каждого класса префикс `Dot`. В `dot-2d` используется `Dot2D*`, потому что
идентификатор не может начинаться с цифры, а `Dot2D` читается лучше, чем
`DotTwoD`.

## Спрашивайте о возможностях, а не о платформах

`DotPlatform.has_threads()`, а не `OS.get_name() == "Web"`. Соответствие не
взаимно однозначное: веб-шаблон *может* быть собран с потоками, а в настольной
сборке может не оказаться того, что вы считали данностью.

## Комментарии объясняют «почему»

В этом коде много неочевидных компромиссов, и соглашение таково: комментарий
объясняет, почему очевидная альтернатива неверна. Иначе следующий читатель
«упростит» её обратно в баг — что случалось достаточно часто, чтобы рассуждение
считалось частью исходного кода.

## Половину этого решает браузер

Настольные системы, мобильные и браузер из одной кодовой базы. Каждое из этих
ограничений закодировано в самом коде, а не оставлено на память читателя:

| Ограничение | Следствие |
| --- | --- |
| Нет UDP; `ENetMultiplayerPeer` отсутствует в веб-шаблоне | `DotTransportENet` добирается до ENet через `ClassDB.instantiate` и `Object.call`, никогда по имени — скрипт, *упоминающий* идентификатор, не компилируется под веб |
| Один слушающий сокет говорит на одном протоколе | Сервер с браузерными клиентами слушает WebSocket, и тогда *все* его клиенты тоже. Поэтому `DotTransportAuto.require_web_clients` по умолчанию `true` |
| Вкладка браузера не может слушать | Веб-сборки — только клиенты |
| Нет `HTTPClient`, только `HTTPRequest` | `DotHttp` безусловно использует `HTTPRequest` |
| Нет потоков, если шаблон не собран с ними | `DotScheduler` режет работу на главном потоке в рамках бюджета на кадр |
| `user://` — зеркало IndexedDB, требующее явного сброса | каждый путь записи вызывает `DotWeb.sync_filesystem()` |
| Квота хранилища, от которой пользователь может отказаться | `DotCloudStore` дожидается `navigator.storage.estimate()` и никогда не считает её безграничной |
| CORS, при котором `fetch()` отказывается сказать, почему не вышло | хостам контента нужны документированные заголовки; тот же origin избавляет от этого |
| **Смонтированный пакет ресурсов нельзя размонтировать ни на одной платформе** | `dot-cloud` даёт каждому контенту пространство имён `id/version`, чтобы ничего никогда не приходилось заменять |

Последнее сформировало [`dot-cloud`](/learn/godot/addons/dot-cloud) сильнее всего
остального.

<Callout type="warning" title="Глобальные `class_name` смонтированного пакета не регистрируются">
Измерено: внутри доставленного `.pck` каждая межфайловая ссылка на тип не
компилируется, так что пакет монтируется, его сцены загружаются, а все скрипты в
нём мертвы. `preload("res://x.gd")` и `extends "res://x.gd"` работают оба.
**Это определяет, как может выглядеть доставляемая игра** — см.
[game-playground](/learn/godot/games#game-playground), где сущности и оружие
именно поэтому являются скриптами, названными по *пути*.
</Callout>

## Ловушки GDScript, за которые коллекция заплатила

Их стоит знать до написания моста, потому что ни одна из них не выдаёт ошибку.

- **`==` связывает сильнее, чем `as`.** `a == [x] as Array[StringName]`
  разбирается как `(a == [x]) as Array[StringName]` и не компилируется.
- **`await x.f().ok` привязывает await к обращению к свойству**, а не к вызову,
  так что корутина никогда не ожидается. Сначала присвойте переменной.
- **`var x := f()`, где `f` возвращает `Variant`, — ошибка разбора** при
  настройках предупреждений этих проектов. Пишите `var x: Variant = f()`.
  `Array.duplicate()` возвращает нетипизированный массив, так что индексация —
  ровно этот случай.
- **Лямбды захватывают локальные переменные по значению.** Счётчик, увеличенный
  внутри обработчика сигнала, снаружи остаётся нулём. Захватывайте `Array` и
  дописывайте в него.
- **`Dictionary` — это ссылка.** Если `to_dictionary()` отдаёт собственный
  словарь, «копия» делит его с оригиналом, и правка одного молча правит другой.
- **`Array.sort()` по `StringName` сортирует не лексикографически** — Godot
  сравнивает интернированные указатели, поэтому два узла могут упорядочить один и
  тот же список по-разному.
- **Компоненты `Vector3` 32-битные, а арифметика GDScript — 64-битная.** Ступни,
  стоящие на `y = 0`, вычисляются как `-2.4e-8`.
- **`String.is_valid_identifier()` для цифры ложно**, потому что идентификатор не
  может с неё *начинаться*.
- **Godot отклоняет RPC, если обе стороны не объявляют одинаковый набор методов
  `@rpc`**, и маршрутизирует его по пути узла относительно корня
  `MultiplayerAPI`. Один лишний метод `@rpc` на одной стороне ломает *все* RPC
  между ними — включая рукопожатие, единственный симптом которого — таймаут.

### Запустить N корутин и дождаться

Оба очевидных варианта неверны. Рабочий приём — голые вызовы-инструкции плюс
**счётчик-поле**, чтобы работник, который ни разу не приостановился, уже был
учтён:

```gdscript
_workers_finished = 0
for i in range(n):
    _worker(i)              # доходит до первого await или до конца
while _workers_finished < n:
    await _worker_done      # в цикл вообще не входим, если все закончили
```

Каждый путь возврата должен увеличить счётчик *и* испустить сигнал.
