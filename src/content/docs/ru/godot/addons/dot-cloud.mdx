Сервер передаёт клиенту манифест; клиент скачивает недостающее, проверяет и
монтирует — на Windows, macOS, Linux, Android, iOS и в браузере.

```gdscript
var cloud := DotCloudClient.new()
add_child(cloud)

cloud.config = DotCloudConfig.new()
cloud.config.trusted_keys = {"default": PUBLIC_KEY_PEM}
await cloud.start()

cloud.phase_changed.connect(func(_p, text): status_label.text = text)
cloud.progress_changed.connect(func(p): bar.value = p.fraction * 100.0)

var res := await cloud.acquire("https://cdn.example.com/dm_arena/manifest.json")
if res.ok:
    get_tree().change_scene_to_file(res.value)
```

Публикация — это безоконная CLI, которая создаёт **статический каталог**:
`manifest.json` плюс дерево `objects/`. Такой каталог раздаёт без всякой
настройки любой веб-сервер или CDN:

```bash
godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    keygen --private keys/content.key --public keys/content.pub

godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    publish --source content/dm_arena --out dist/dm_arena \
    --id dm_arena --version 1.2.0 --entry arena.tscn --key keys/content.key
```

## Два ограничения, которые определили всё

**Godot не умеет размонтировать пакет ресурсов.** Ни медленно, ни в обход — API
просто нет. Поэтому каждый набор контента получает собственный путь с версией,
`res://<root>/<content_id>/<version>/`, и заменять никогда ничего не нужно.
«Выгрузить» означает отпустить ссылки, а не вернуть себе таблицу файлов. Именно
этот факт делает смену игры во время работы возможной вообще.

**Неподписанный контент — это удалённое выполнение кода.** Пакет Godot может
содержать скрипты, значит манифест решает, что будет выполнено.
`require_signed_manifests` включён по умолчанию, а конфигурация отказывается
проходить проверку без доверенного ключа. Для локальной сети или собственного
сервера это можно выключить; предупреждение будет каждый раз.

## Что он делает

- **Кэш с адресацией по содержимому.** Файлы лежат под своим SHA-256, поэтому две
  игры с общим ассетом скачают его один раз, а повторная публикация докачает
  только изменившееся.
- **Возобновляемые параллельные загрузки.** Переключение между зеркалами,
  докачка по HTTP-диапазонам, размыкатель на каждый источник, ограничение
  полосы, честный прогресс и честная оценка времени.
- **Три источника.** HTTP/CDN, локальный каталог (разработка, локальная сеть,
  встроенный контент) и внутриканальный — по игровому соединению, для сервера без
  веб-хостинга.
- **Учёт квоты.** Оценки хранилища в браузере, потолки для мобильных и вытеснение
  давно не использовавшегося, которое никогда не вытесняет используемый контент.

## Что проверяется при монтировании

Между загрузкой и монтированием пакет проходит четыре правила, каждое из которых
выросло из чьего-то измеренного сбоя:

- **Сначала читается его `requires.json`.** Скрипты пакета компилируются против
  дополнений хоста, так что пакет, которому нужно более новое дополнение, раньше
  падал на разборе посреди загрузки. Теперь он отвергается до загрузки любого
  скрипта с сообщением *«Этой игре нужен dot-net API уровня 3 или новее; у этого
  клиента уровень 2.»* — см.
  [уровни API дополнений](/learn/godot/addons/dot-core#addon-api-levels-dotaddonapi).
  `host_role` называет сторону.
- **Идентификатор контента может называть владельца: `<owner>/<name>`.** `/` не
  может встречаться ни в одной из половин, так что ключ с областью `alice/*`
  точен — склеенное `alice_bob` не отличило бы `alice` + `bob_x` от `alice_bob` +
  `x`. Каждый сегмент должен быть slug-ом; голый идентификатор, каким является
  каждый собственный пакет, по-прежнему проходит проверку.
- **Один идентификатор не может значить две вещи.** Второй манифест для того же
  `content_id@version` от другого издателя отвергается с `CODE_CONFLICT`, а не
  получает монтирование первого, — пакет может содержать скрипты, а «первый» —
  это чужой код. Равный манифест, перечитанный из сети, по-прежнему дешёвая
  пустая операция.
- **Смонтированный пакет регистрирует собственные uid и не может занимать чужие.**
  Импортированный ресурс (`.glb`, `.png`) ссылается на соседей по UID, который не
  переживает монтирования в другом месте; монтировщик направляет каждый UID на
  смонтированную копию. UID, который хост уже держит, отвергается и
  сообщается — иначе каждый `load("uid://…")` в сборке можно было бы перенаправить
  на скачанный контент.

<Callout type="warning" title="Импортированные результаты поставляются в `_imported/`, а не в `.godot/`">
Опубликованный пакет несёт импортированные результаты движка, и раньше они лежали
по настоящему пути, `.godot/imported/`. Linux читает их оттуда безупречно; **веб-экспорт
не может**, и вся игра отказывалась запускаться в браузере. Теперь результаты
поставляются в `_imported/`, а каждый маркер `.import` переписан так, чтобы
называть, куда лёг результат. Иначе отсутствующая графика в смонтированном пакете
проявляется лишь предупреждениями — пакет проверяется, монтируется и загружается
без своих текстур.
</Callout>

## Где подключается игра

<Params>
  <Param name="Наследник DotCloudSource">
    `source_name()`, `is_supported()`, `can_serve(manifest)`, `fetch(...)`. Три
    поставляются — `DotCloudSourceHttp`, `DotCloudSourceLocal`,
    `DotCloudSourceNetchan`, — а четвёртый ваш: торрент, CDN конкретной
    платформы, генератор подписанных ссылок S3.

    `fetch` **обязан** писать в `DotCloudStore.partial_path` для хеша файла, по
    возможности продолжать с `partial_size` и завершать через `commit_partial`.
    Это единственное место, где проверяется хеш, а запись прямо в каталог
    объектов — ровно тот путь, которым непроверенный контент оказывается
    смонтированным.
  </Param>
  <Param name="can_serve() против is_supported()">
    Это различие себя оправдывает. Источник может быть совершенно исправен и всё
    равно не иметь способа добраться до *этого* манифеста: HTTP-источник без
    `base_urls` против манифеста без зеркал. Вернуть неудачу из `can_serve`
    означает «пропусти меня для этого манифеста, и вот почему», и это **не**
    засчитывается размыкателю.
  </Param>
  <Param name="priority" type="int">
    Есть у каждого источника. Меньшее значение идёт первым; внутриканальный
    запасной вариант намеренно стоит последним.
  </Param>
  <Param name="DotCloudConfig">
    `trusted_keys`, `require_signed_manifests`, `cache_bytes`,
    `mobile_cache_bytes`, `web_quota_fraction`, `parallel_downloads`,
    `max_attempts_per_file`, `throttle_bytes_per_sec`, `file_timeout_sec`, `cache_dir`,
    `verify_before_mount`, `verify_cache_on_start`, `resume_downloads`, `enforce_mount_prefix`. Слоистая, как любой `DotConfig`.
  </Param>
  <Param name="manifest_url_template / manifest_url_fallbacks" type="DotCloudClient">
    Откуда запрашивается манифест, по базовому URL, идентификатору и версии. По умолчанию `{base}/{id}/{version}/manifest.json` — именно так публикует сайт; `manifest_url_fallbacks` перечисляет другие формы, пробуемые после него, по каждой базе, потому что в одном источнике могут лежать пакеты, опубликованные в двух раскладках, и повторная публикация всех из них — не условие для запуска.
  </Param>
  <Param name="Сигналы">
    У `DotCloudClient`: `phase_changed`, `progress_changed`, `content_ready`, `content_released`, `failed`. Подробности по файлам — у загрузчика: `file_finished`, `sync_finished`.
  </Param>
</Params>

## Интерфейс контента, которого ждут другие дополнения

Зарегистрируйте `DotCloudClient`, и он опубликует себя под именем
`dot_cloud_client`. Загрузчик `dot-map` и смена игры в `dot-server` обращаются к
нему по этому имени и вызывают:

```gdscript
ensure(content_id: String, version: String) -> DotResult
is_mounted(content_id: String, version: String) -> bool
```

Большинство дополнений обращаются к ним через `DotContent` в
[`dot-core`](/learn/godot/addons/dot-core#downloadable-content-dotcontent) —
единственного общего вызывающего, — благодаря чему части аватаров, пропсы, NPC,
транспорт и предметы, называющие контент, теперь действительно его скачивают.

<Callout type="warning" title="Отсутствие облачного клиента — законная конфигурация">
Каждое место вызова трактует «нет `dot_cloud_client`» как «в этом развёртывании
контент лежит внутри сборки» — что законный выбор для вашей собственной игры и
потому неотличимо от клиента, который не смог зарегистрироваться. Развёртывание
TMC вообще не поставляет контента в сборке: каждая игра, каждая импортированная
карта и лобби — это пакет, который скачивает это дополнение. Когда доставляемая
карта или игра молча ничего не делает, смотрите сначала в реестр.
</Callout>
