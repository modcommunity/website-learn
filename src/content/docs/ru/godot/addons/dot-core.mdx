Общий слой под всем остальным и **единственная жёсткая зависимость коллекции**.
Он нацелен на настольные системы, мобильные и браузер из одной кодовой базы и
кодирует браузерные ограничения, а не делает вид, что их нет.

```bash
cp -r dot-core/addons/dot_core моя-игра/addons/
godot --headless --path . res://examples/capability_report.tscn
```

## Что внутри

| | |
| --- | --- |
| `DotResult` / `DotError` | Тип возврата всего, что может не получиться. Стабильные значения `CODE_*`, по которым ветвятся; чтение `.value` у неудачи вызывает ошибку, а не возвращает значение по умолчанию. |
| `DotPlatform` | Кэшируемое определение возможностей — потоки, UDP, приём подключений, монтирование пакетов, семейство хранилища, уникальный id. Спрашивайте о возможностях, а не об именах платформ. |
| `DotNodeRef` | Редактируемое в инспекторе описание того, *какой это узел*: относительный, абсолютный, группа, реестр, предок или потомок по типу, либо создать-если-нет. |
| `DotConfig` | Слоистая конфигурация: экспортированные значения по умолчанию < файл < окружение < командная строка, с рефлексивным обнаружением ключей и защитой секретов. |
| `DotRegistry` / `DotRegistryBus` | Поиск по имени и сигналы, которые статический класс объявить не может. |
| `DotScheduler` / `DotJob` | Долгая работа порциями. Рабочие потоки там, где они есть, и бюджет времени на кадр там, где их нет. |
| `DotTransport` | Сменный транспорт для мультиплеера. `DotTransportAuto` выбирает между WebSocket и ENet и пишет в журнал почему. |
| `DotHttp` | Клиент на `HTTPRequest` с повторами, джиттеризованной задержкой, `Retry-After`, докачкой по диапазонам и пулом соединений. |
| `DotLog` / `DotLogBus` / `DotLogSink` | Журналирование по уровням и каналам, со структурированными полями, ротацией файлов и пересылкой по UDP. |
| `DotPaths` | Санация путей, которая *отказывает* при выходе за пределы, а не «чистит» его; атомарная запись и сброс веб-файловой системы. |
| `DotHash` / `DotHashJob` | SHA-256, HMAC, сравнение за постоянное время, base64url, токены из CSPRNG. |
| `DotRateLimiter` | Ведро токенов, применяемое на каждом пути, который может нагружать клиент. |
| `DotSemVer` | Сравнение версий — для контента и минимальных версий движка. |
| `DotWeb` | Только браузерные вызовы: синхронизация файловой системы, определение защищённого контекста, оценки хранилища. |

## Где подключается игра

<Params>
  <Param name="Наследник DotTransport">
    `_create_server`, `_create_client`, `_transport_name`, `_is_available`,
    `supports_web_clients`, `scheme`. Доступность проверяется *до*
    использования, так что непригодный транспорт падает при старте с
    объяснением, а не превращается в нулевой peer тремя вызовами позже.
  </Param>
  <Param name="Наследник DotJob">
    `_step` (ограниченный кусок; true, если осталось ещё), `_progress`,
    `_setup`, `_teardown`, `is_thread_safe`. Хешируйте блок, а не файл: планировщик
    может перестать звать `_step`, но прервать уже начавшийся вызов не может.
  </Param>
  <Param name="Наследник DotConfig">
    `env_prefix()`, `cli_prefix()`, `sensitive_keys()`, `validate()`. Объявите
    свойства `@export` — и слои, рефлексия и экран настроек получатся сами.
  </Param>
  <Param name="DotLogSink или DotLog.add_sink(callable)">
    Куда уходят записи. Вариант с `Callable` — одна строка; класс берёт на себя
    файлы, ротацию и пересылку.
  </Param>
  <Param name="DotNodeRef у каждого компонента">
    Общий для коллекции ответ на вопрос «какой узел». Каждый узел каждого
    дополнения экспортирует хотя бы одну такую ссылку.
  </Param>
</Params>

## `DotResult` — не факультативная вежливость

```gdscript
var res := await cloud.acquire(url)
if not res.ok:
    if res.error.code == DotError.CODE_RATE_LIMITED:
        retry_after(res.error.retry_after)
    return
var scene_path: String = res.value
```

Ветвитесь по `DotError.CODE_*`, никогда — по тексту сообщения. `res.wrap(...)`
добавляет контекст, не теряя причину, так что неудача тремя слоями ниже всё ещё
скажет, чем она занималась на каждом уровне.

## `DotScheduler` и браузер

`DotScheduler` выполняет задачи в рабочих потоках там, где они есть у сборки, и
режет их на главном потоке в рамках бюджета на кадр там, где их нет: у
веб-экспорта потоков нет, если шаблон не собран с ними, и правильный вопрос —
`DotPlatform.has_threads()`, а не `OS.get_name()`.

<Callout type="warning" title="Сигнал `finished` задачи всегда доставляется в главном потоке">
Однажды это было не так: `await` возобновлялся в рабочем потоке, и следующая
строка трогала дерево сцены вне главного потока. `_teardown` выполняется в том
потоке, который завершил задачу, и предназначен только для потокобезопасных API;
всё, что трогает дерево, место в обработчике `finished`.
</Callout>

## Транспорты

`DotTransportAuto` используется по умолчанию и выбирает за вас. Этот выбор — не
предпочтение:

- **У браузера нет UDP**, а `ENetMultiplayerPeer` отсутствует в веб-шаблоне —
  поэтому `DotTransportENet` добирается до ENet через `ClassDB.instantiate` и
  `Object.call`, никогда по имени. Скрипт, который лишь *упоминает*
  идентификатор, не компилируется под веб.
- **Один слушающий сокет говорит на одном протоколе.** Сервер, которому нужны
  браузерные клиенты, слушает WebSocket, и тогда *все* его клиенты тоже. Поэтому
  `require_web_clients` по умолчанию `true`.

<Callout type="info" title="`DotWeb.is_secure_context()` — это не «страница по HTTPS»">
Браузер считает `http://localhost` и `http://127.0.0.1` доверенными источниками,
так что на обычной HTTP-странице это истина — тогда как блокировка смешанного
содержимого, то самое правило, которое решает, разрешён ли `ws://`, именно эти
источники и освобождает. Повышение по неверному признаку — причина, по которой
ничто отсюда никогда не загружалось в браузере.
</Callout>
