Ein Server reicht einem Client ein Manifest; der Client lädt herunter, was ihm
fehlt, prüft es und hängt es ein — unter Windows, macOS, Linux, Android, iOS und
im Browser.

```gdscript
var cloud := DotCloudClient.new()
add_child(cloud)

cloud.config = DotCloudConfig.new()
cloud.config.trusted_keys = {"default": PUBLIC_KEY_PEM}
await cloud.start()

cloud.phase_changed.connect(func(_p, text): status_label.text = text)
cloud.progress_changed.connect(func(p): bar.value = p.fraction * 100.0)

var res := await cloud.acquire("https://cdn.example.com/dm_arena/manifest.json")
if res.ok:
    get_tree().change_scene_to_file(res.value)
```

Veröffentlicht wird über eine headless CLI, die ein **statisches Verzeichnis**
erzeugt — eine `manifest.json` plus einen `objects/`-Baum —, das jeder Webserver
und jedes CDN ohne Konfiguration ausliefert:

```bash
godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    keygen --private keys/content.key --public keys/content.pub

godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    publish --source content/dm_arena --out dist/dm_arena \
    --id dm_arena --version 1.2.0 --entry arena.tscn --key keys/content.key
```

## Die zwei Beschränkungen, die alles geformt haben

**Godot kann ein Ressourcenpaket nicht aushängen.** Nicht langsam, nicht mit
einem Trick — die API existiert nicht. Deshalb bekommt jeder Inhaltssatz seinen
eigenen versionierten Pfad, `res://<root>/<content_id>/<version>/`, und nichts
muss je ersetzt werden. „Entladen“ heißt Referenzen fallen lassen, nicht die
Dateitabelle zurückgewinnen. Diese eine Tatsache ist der Grund, warum ein
Spielwechsel zur Laufzeit überhaupt funktioniert.

**Unsignierter Inhalt ist Remote Code Execution.** Ein Godot-Paket kann Skripte
enthalten, also entscheidet ein Manifest, was ausgeführt wird.
`require_signed_manifests` ist standardmäßig an, und die Konfiguration
verweigert die Prüfung ohne vertrauenswürdigen Schlüssel. Für ein LAN oder einen
eigenen Server kannst du es abschalten; es warnt jedes Mal.

## Was es tut

- **Inhaltsadressierter Cache.** Dateien liegen unter ihrem SHA-256, also laden
  zwei Spiele mit gemeinsamem Asset es nur einmal, und ein erneutes
  Veröffentlichen lädt nur das Geänderte nach.
- **Fortsetzbare parallele Downloads.** Mirror-Umschaltung, HTTP-Range-Resume,
  ein Circuit Breaker pro Quelle, Bandbreitendrosselung sowie ehrlicher
  Fortschritt und ehrliche Restzeit.
- **Drei Quellen.** HTTP/CDN, ein lokales Verzeichnis (Entwicklung, LAN,
  mitgelieferter Inhalt) und in-band über die Spielverbindung für einen Server
  ohne Webhosting.
- **Kontingentbewusstsein.** Browser-Speicherschätzungen, mobile Obergrenzen und
  eine LRU-Verdrängung, die nie Inhalt verdrängt, der gerade benutzt wird.

## Was das Einhängen prüft

Zwischen Download und Einhängen wird ein Paket an vier Regeln gemessen, die jede
aus einem Fehler stammen, den jemand gemessen hat:

- **Seine `requires.json` wird zuerst gelesen.** Die Skripte eines Pakets
  kompilieren gegen die Addons des Hosts, sodass eines, das ein neueres Addon
  brauchte, früher mitten im Laden beim Parsen scheiterte. Jetzt wird es
  abgelehnt, bevor ein Skript lädt, mit *„This game needs dot-net API level 3 or
  newer; this build has level 2.“* — siehe
  [Addon-API-Levels](/learn/godot/addons/dot-core#addon-api-levels-dotaddonapi).
  `host_role` benennt die Seite.
- **Eine Content-Id darf ihren Eigentümer nennen: `<owner>/<name>`.** `/` kann in
  keiner der beiden Hälften vorkommen, also ist ein Schlüssel mit Geltungsbereich
  `alice/*` exakt — ein abgeflachtes `alice_bob` könnte `alice` + `bob_x` nicht
  von `alice_bob` + `x` unterscheiden. Jedes Segment muss ein Slug sein; eine
  bloße Id, wie sie jedes Erstanbieter-Paket hat, validiert weiterhin.
- **Eine Id kann nicht zwei Dinge bedeuten.** Ein zweites Manifest für dieselbe
  `content_id@version` von einem anderen Herausgeber wird mit `CODE_CONFLICT`
  abgelehnt, statt den Mount des ersten zu bekommen — ein Paket kann Skripte
  enthalten, und „das des ersten“ ist der Code von jemand anderem. Ein gleiches,
  erneut von der Leitung gelesenes Manifest ist weiterhin ein billiges No-op.
- **Ein eingehängtes Paket registriert seine eigenen UIDs und darf keine fremden
  übernehmen.** Ein importiertes Asset (eine `.glb`, eine `.png`) verweist per UID
  auf seine Geschwister, und die überlebt das Einhängen an anderer Stelle nicht;
  der Mounter richtet jede UID auf die eingehängte Kopie. Eine UID, die der Host
  bereits hält, wird abgelehnt und gemeldet, sonst könnte jedes
  `load("uid://…")` im Build auf heruntergeladenen Inhalt umgebogen werden.

<Callout type="warning" title="Importierte Ausgaben werden unter `_imported/` ausgeliefert, nie unter `.godot/`">
Ein veröffentlichtes Paket trägt die importierten Ausgaben der Engine, und die
lagen früher an ihrem echten Pfad, `.godot/imported/`. Linux liest das einwandfrei
zurück; **ein Web-Export kann es nicht**, und das ganze Spiel weigerte sich, im
Browser zu starten. Ausgaben werden jetzt unter `_imported/` ausgeliefert, und
jeder `.import`-Marker wird so umgeschrieben, dass er nennt, wohin die Ausgabe
gekommen ist. Fehlende Grafik in einem eingehängten Paket zeigt sich sonst nur
als Warnungen — das Paket verifiziert, hängt sich ein und lädt, ohne seine
Texturen.
</Callout>

## Wo sich ein Spiel einklinkt

<Params>
  <Param name="DotCloudSource-Unterklasse">
    `source_name()`, `is_supported()`, `can_serve(manifest)`, `fetch(...)`. Drei
    werden mitgeliefert — `DotCloudSourceHttp`, `DotCloudSourceLocal`,
    `DotCloudSourceNetchan` — und die vierte ist deine: ein Torrent, ein
    plattformspezifisches CDN, ein Erzeuger signierter S3-URLs.

    Ein `fetch` **muss** in `DotCloudStore.partial_path` für den Hash der Datei
    schreiben, wo möglich ab `partial_size` fortsetzen und über `commit_partial`
    abschließen. Das ist die einzige Stelle, an der der Hash geprüft wird, und
    direkt ins Objektverzeichnis zu schreiben ist genau der Weg, auf dem
    ungeprüfter Inhalt eingehängt wird.
  </Param>
  <Param name="can_serve() gegenüber is_supported()">
    Die Unterscheidung verdient sich ihren Platz. Eine Quelle kann völlig gesund
    sein und trotzdem keinen Weg zu *diesem* Manifest haben — eine HTTP-Quelle
    ohne `base_urls` gegenüber einem Manifest ohne Mirror. Aus `can_serve` einen
    Fehlschlag zurückzugeben heißt „überspring mich für dieses Manifest, und hier
    ist der Grund“, und wird **nicht** dem Circuit Breaker angerechnet.
  </Param>
  <Param name="priority" type="int">
    An jeder Quelle. Niedriger läuft zuerst; der In-band-Rückfall steht bewusst
    ganz hinten.
  </Param>
  <Param name="DotCloudConfig">
    `trusted_keys`, `require_signed_manifests`, `cache_bytes`,
    `mobile_cache_bytes`, `web_quota_fraction`, `parallel_downloads`,
    `max_attempts_per_file`, `throttle_bytes_per_sec`, `file_timeout_sec`, `cache_dir`,
    `verify_before_mount`, `verify_cache_on_start`, `resume_downloads`, `enforce_mount_prefix`. Geschichtet wie jede `DotConfig`.
  </Param>
  <Param name="manifest_url_template / manifest_url_fallbacks" type="DotCloudClient">
    Wo ein Manifest angefragt wird, aus einer Basis-URL, einer Id und einer Version. Der Standard ist `{base}/{id}/{version}/manifest.json`, was die Seite veröffentlicht; `manifest_url_fallbacks` listet weitere Formen, die danach je Basis versucht werden, weil ein Ursprung Pakete in zwei Layouts halten kann und das erneute Veröffentlichen aller keine Voraussetzung fürs Starten ist.
  </Param>
  <Param name="Signale">
    Auf `DotCloudClient`: `phase_changed`, `progress_changed`, `content_ready`, `content_released`, `failed`. Details je Datei liegen am Downloader: `file_finished`, `sync_finished`.
  </Param>
</Params>

## Die Inhaltsschnittstelle, die andere Addons erwarten

Registriere einen `DotCloudClient`, und er veröffentlicht sich unter
`dot_cloud_client`. Der Lader von `dot-map` und der Spielwechsel von
`dot-server` erreichen ihn über diesen Namen und rufen:

```gdscript
ensure(content_id: StringName, version: String = "", groups := PackedStringArray(), manifest_url := "") -> DotResult
is_mounted(content_id: StringName, version: String = "") -> bool
```

Die meisten Addons erreichen sie über `DotContent` in
[`dot-core`](/learn/godot/addons/dot-core#downloadable-content-dotcontent), den
einen gemeinsamen Aufrufer — wodurch Avatar-Teile, Props, NPCs, Fahrzeuge und
Gegenstände, die Inhalt benennen, ihn jetzt tatsächlich holen.

<Callout type="warning" title="Ein fehlender Cloud-Client ist eine legitime Konfiguration">
Jede Aufrufstelle behandelt „kein `dot_cloud_client`“ als „diese Bereitstellung
liefert ihre Inhalte im Build mit“ — was für das eigene Spiel eine legitime Wahl ist und daher nicht
von einem Client zu unterscheiden ist, der sich nicht registriert hat. Die eigene Bereitstellung von TMC liefert überhaupt keinen Inhalt im Build mit: Jedes Spiel, jede importierte Karte und die Lobby ist ein Paket, das dieses Addon holt. Wenn eine
ausgelieferte Karte oder ein ausgeliefertes Spiel still gar nichts tut, sieh
zuerst in die Registry.
</Callout>
