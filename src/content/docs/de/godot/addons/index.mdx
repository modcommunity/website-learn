Fünfzig Addons, die zusammenarbeiten und — abgesehen von `dot-core` — auch
einzeln funktionieren. Jedes ist ein eigenes Repository unter
[`modcommunity`](https://github.com/modcommunity), jedes liefert einen Ordner
`addons/<name>/` aus, und jedes hat seine eigene Testsuite ohne Anzeige.

<Callout type="info" title="Nur `dot-core` ist je eine harte Abhängigkeit">
Alles in einer *optional*-Spalte wird per Duck-Typing oder über
[`DotRegistry`](/learn/godot/conventions#dotregistry-instead-of-autoloads)
aufgelöst, und keines dieser Addons nennt die Bezeichner eines anderen — denn in
GDScript scheitert ein Skript, das einen fehlenden `class_name` auch nur
*erwähnt*, beim Parsen und reißt alles mit, was es referenziert.

Sieben sind die Ausnahme, die die Regel bestätigt, und jedes sagt es selbst:
`dot-npc-ai` und `dot-npc-ai-director` brauchen `dot-npc`;
`dot-player-controller`, `dot-player-char` und `dot-player-class` brauchen
`dot-player`; und `dot-server-query` und `dot-server-security` brauchen
`dot-server`, weil jedes davon ein *Teil* eines Servers ist und nicht etwas, das
ein Server bei Gelegenheit befragt.
</Callout>

## Das Fundament

| | Hängt ab von | |
| --- | --- | --- |
| [dot-core](/learn/godot/addons/dot-core) | — | Protokollierung, Plattformfähigkeiten, Pfade, konfigurierbare Knotenreferenzen, geschichtete Konfiguration, Aufgaben mit Frame-Budget, Multiplayer-Transporte, HTTP und reproduzierbare Zufallsströme. |

## Der Spieler

Wer in der Sitzung ist, was ihn steuert, wie er aussieht und was er ist. Jedes
Spiel der Sammlung benutzt diese.

| | Hängt ab von | |
| --- | --- | --- |
| [dot-player](/learn/godot/addons/dot-player) | dot-core | Die eine Zeile, die alles andere liest: wer da ist, welche Seite, lebendig, was ihn darstellt. Plätze überstehen eine Wiederverbindung. |
| [dot-player-controller](/learn/godot/addons/dot-player-controller) | dot-core, dot-player | Alles, was einen Spieler antreibt. Ego-Bewegung, geschrieben um vorhergesagt und abgeglichen zu werden, dritte Person mit Orbit-Rig, und der Wechsel zwischen beiden. |
| [dot-player-char](/learn/godot/addons/dot-player-char) | dot-core, dot-player | Wie ein Spieler aussieht und wie groß er ist: die Maße, über die sich fünf Systeme einig sein müssen, ein Anpassungsdokument, ein 3D-Rig, ein 2D-Sheet, eine Fortbewegungs-Zustandsmaschine. |
| [dot-player-class](/learn/godot/addons/dot-player-class) | dot-core, dot-player | Was ein Spieler *ist*, als begrenztes Dokument mit Limits und Berechtigungen. Eine Änderung greift beim nächsten Spawn. |
| [dot-physics](/learn/godot/addons/dot-physics) | dot-core | Benannte Kollisions-Layouts, Engine-Profile benannt nach ihrem Spielgefühl, eine Oberflächentabelle und Abfragen gegen Layer-Namen statt Zahlen. |
| [dot-spawn](/learn/godot/addons/dot-spawn) | dot-core | Wo etwas die Welt betritt und warum dort. Punkte und Flächen, Bedingungen mit Veto, sechs Auswahlmodi, Wellen, Spawnschutz. |
| [dot-team](/learn/godot/addons/dot-team) | dot-core, *optional* dot-spectate | Seiten, die das Match überdauern, eine Beitritts-, Wechsel- und Sperrpolitik, und ein Autobalance, das deterministisch und erklärbar ist. |

## Identität und Inhalte

| | Hängt ab von | |
| --- | --- | --- |
| [dot-auth](/learn/godot/addons/dot-auth) | dot-core | Geräte-Code-Authentifizierung gegen das Backbone, signierte Verbindungstickets, serverseitige Identität. |
| [dot-user](/learn/godot/addons/dot-user) | dot-core | Profile, die einer Person von Server zu Server folgen, unter einer pseudonymen ID je Geltungsbereich. |
| [dot-user-avatar](/learn/godot/addons/dot-user-avatar) | dot-core | Avatare als Daten: ein begrenztes Dokument, das ein Server gegen ein Schema und Berechtigungen prüft, ohne ein Mesh zu laden. |
| [dot-platform](/learn/godot/addons/dot-platform) | dot-core, dot-server | Führt Identität, Profil und Avatar zu einem Aufnahmeablauf zusammen und bindet ihn an einen Server. |
| [dot-cloud](/learn/godot/addons/dot-cloud) | dot-core | Inhaltsauslieferung zur Laufzeit: signierte Manifeste, inhaltsadressierter Cache, fortsetzbare parallele Downloads, Pakete unter Namensräumen gemountet. |

## Server und Leitung

| | Hängt ab von | |
| --- | --- | --- |
| [dot-net](/learn/godot/addons/dot-net) | dot-core | Netcode: Tick-Synchronisation, bitgepacktes Wire-Format, Zustandsreplikation, Snapshot-Interpolation, Client-seitige Vorhersage, Lag-Kompensation, Interest Management. |
| [dot-server](/learn/godot/addons/dot-server) | dot-core, *optional* dot-auth + dot-cloud | Der dedizierte Server: Konsole, RCON, Rechte, Moderation, Abstimmungen, Module, Spielwechsel im laufenden Betrieb. |
| [dot-server-query](/learn/godot/addons/dot-server-query) | dot-core, dot-server, *optional* dot-stats | Die Serverseite einer Abfrage: DQP — mit Challenge, in Abschnitten, bedingt abfragbar und aus dem Browser erreichbar — und das gesamte A2S, beide aus einem Snapshot beantwortet. |
| [dot-server-security](/learn/godot/addons/dot-server-security) | dot-core, dot-server, *optional* dot-moderation + dot-chat + dot-auth | Härtung als Konfiguration: Regeln über gleitende Fenster, die von Verwarnung über Gag und Kick bis zum Bann eskalieren; Anti-Cheat, das Bewiesenes von Verdächtigem trennt; und externe Bannlisten. Wird im Trockenlauf ausgeliefert. |
| [dot-browser](/learn/godot/addons/dot-browser) | dot-core | Die andere Hälfte dieser Abfragen: ein Client. DQP über UDP, dasselbe als JSON über WebSocket, und A2S — hinter einem Listenmodell mit Quellen, Filtern und Favoriten. |
| [dot-peer-to-peer](/learn/godot/addons/dot-peer-to-peer) | dot-core | Sitzungen, die Spieler füreinander hosten: Beitrittscodes, Bereitschaft, eine Host-Wahl als reine Funktion der Mitgliederliste, und eine ehrliche Darstellung von NAT. |
| [dot-moderation](/learn/godot/addons/dot-moderation) | dot-core | Banns, Kicks, Gags, Voice-Mutes und Verwarnungen als ein dauerhafter Datensatz. Veröffentlicht die Mute- und Bannquellen, die die anderen befragen. |
| [dot-chat](/learn/godot/addons/dot-chat) | dot-core, *optional* dot-moderation | Serverautoritativer Textchat: Kanäle mit Publikumsregel, Bereinigung, Ratenbegrenzung, Verlauf, Befehle. |
| [dot-voice](/learn/godot/addons/dot-voice) | dot-core | Sprachchat: Aufnahme, austauschbarer Codec, ein Jitter-Puffer je Sprecher, und serverseitiges Routing an alle, ein Team oder einen Radius. |
| [dot-spectate](/learn/godot/addons/dot-spectate) | dot-core | Wer wem zusieht und was der Server sehen lässt: sieben Beobachtermodi, eine Force-Camera-Politik, die Todeskamera-Kette, eine Übertragungsverzögerung. |
| [dot-vote](/learn/godot/addons/dot-vote) | dot-core, *optional* dot-server + dot-map | Abstimmen, was als Nächstes läuft, als eine konfigurierbare Maschine: rtv, Nominierungen, vier Auszählverfahren, fünf Stichentscheide. |

| [dot-inventory](/learn/godot/addons/dot-inventory) | dot-core, *optional* dot-loadout | Ein vollständiges Inventar als Dokument: Raster, Stapel, Gewicht, Ausrüstung, verschachtelte Behälter. Jede Änderung ist eine Operation. |
| [dot-economy](/learn/godot/addons/dot-economy) | dot-core | Eine rundenbasierte Kaufwirtschaft: Geld, ein Shop, ein Kauffenster, Erstattungen und die Verlustbonus-Leiter. Sie verkauft IDs und gewährt nichts. |
| [dot-match](/learn/godot/addons/dot-match) | dot-core | Die Match-Schleife: Aufwärmen, Runden, Punkte, Teams, Spawnen, Respawnen. Alles in Ticks, von einem Aufruf getrieben. |
| [dot-objective](/learn/godot/addons/dot-objective) | dot-core | Worum es in einer Runde *geht*: ein Kontrollpunkt, eine Bombe, ein Wagen, eine Flagge, eine Eskorte, eine Standhalte-Uhr. |
| [dot-2d](/learn/godot/addons/dot-2d) | dot-core | Das 2D-Gegenstück: deterministisch von oben, Schub- und massebasierte Bewegung, ein räumlicher Hash für Tausende Entitäten, deterministische Streufelder. |

## Die Welt

| | Hängt ab von | |
| --- | --- | --- |
| [dot-npc](/learn/godot/addons/dot-npc) | dot-core | Was ein NPC *ist*: ein Katalog, ein Bevölkerungsbudget, Wahrnehmung, die sich auf ein Ziel festlegt, und Navigation, erzeugt aus den Konstanten der Karte selbst. |
| [dot-npc-ai](/learn/godot/addons/dot-npc-ai) | dot-core, dot-npc | Wie einer *entscheidet*: Verhaltensbäume, die fortsetzen statt neu zu starten, Zustandsmaschinen, ein Blackboard, das vergisst, und ein Charakter statt einer Schwierigkeitsstufe. |
| [dot-npc-ai-director](/learn/godot/addons/dot-npc-ai-director) | dot-core, dot-npc | Bevölkerung und Tempo: aufbauen, halten, abklingen, entspannen — getrieben davon, was die Spieler gerade erleben, nicht von einem Timer. |
| [dot-vehicle](/learn/godot/addons/dot-vehicle) | dot-core | Fahrzeuge zum Fahren, Mitfahren und Herausschießen — und die Übergabe, der Teil, den jedes Spiel falsch macht. |
| [dot-map](/learn/godot/addons/dot-map) | dot-core, *optional* dot-cloud | Karten als Inhalt statt als Builds: ein Katalog, eine Rotation, Nominierungen und Abstimmungen, und ein Loader, der über dot-cloud lädt. |
| [dot-props](/learn/godot/addons/dot-props) | dot-core | Eine Sandbox-Schicht: spawnbare Props, Budgets je Spieler, ein Undo-Stapel, eine Physikkanone und eine Gravitationskanone. Serverautoritativ. |
| [dot-procedural-generation](/learn/godot/addons/dot-procedural-generation) | dot-core | Generierung als geordnete Pipeline über ein Dokument, mit einem Validator, der eine Karte ablehnt, die niemand beenden könnte. |

## Der Mensch an der Tastatur

| | Hängt ab von | |
| --- | --- | --- |
| [dot-ui](/learn/godot/addons/dot-ui) | dot-core | Bildschirme, HUD und Menüs ganz ohne Grafik. Ein Screen-Stack, ein Einstellungspanel, erzeugt aus jeder `DotConfig`, und eine Tastenbelegung mit Konflikterkennung. |
| [dot-settings](/learn/godot/addons/dot-settings) | dot-core | Einstellungen als begrenztes Dokument mit drei Geltungsbereichen — einschließlich der wenigen, die ein Server begrenzen darf und niemals lesen darf. |
| [dot-console](/learn/godot/addons/dot-console) | dot-core, *optional* dot-server | Die Konsole des Spielers: eine physische Taste, eine Zeile, Verlauf, Vervollständigung, ein begrenzter Rückblick — und Befehls*quellen* statt eines zweiten Befehlssystems. |
| [dot-audio](/learn/godot/addons/dot-audio) | dot-core | Spiel-Audio, das kein Audio ausliefert: ein Katalog von IDs, gepoolte Stimmen mit Prioritätsverdrängung, Gleichzeitigkeitsgrenzen, Distanz-Culling, Musik und Ducking. |
| [dot-fx](/learn/godot/addons/dot-fx) | dot-core | Visuelle Effekte als Dokumente: gepoolt, budgetiert, in Qualitätsstufen, distanzgecullt. Ein Effekt ändert nie die Simulation. |
| [dot-lighting](/learn/godot/addons/dot-lighting) | dot-core | Die Beleuchtung einer Welt als Dokument: Sonne, Umgebungslicht, Nebel, Himmel und Nachbearbeitung, gelesen aus dem, was die Karte mitbringt, mit einem Qualitätsprofil je Maschine. Nicht dot-fx, denn Beleuchtung darf man nicht einfach weglassen. |
