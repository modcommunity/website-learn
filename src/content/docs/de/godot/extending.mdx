**Nichts in der Sammlung sollte einen Fork verlangen.** Eine Änderung, die einen
der Punkte unten schwerer erreichbar macht, gilt als Regression — auch wenn alle
Tests weiter durchlaufen.

Es gibt fünf Arten von Erweiterungspunkten, und zu wissen, welche man vor sich
hat, sagt einem, wo man sie sucht.

<Params>
  <Param name="Eine Basisklasse ableiten">
    Eine abstrakte Klasse mit einer dokumentierten Menge zu überschreibender
    Methoden mit `_`-Präfix. Speicher, Quellen, Codecs, Regeln, Bildschirme,
    Module. Rund dreißig davon.
  </Param>
  <Param name="Ein Callable zuweisen">
    Ein Feld an einem Knoten, meist `*_fn` oder `*_source` genannt, das genau die
    eine Frage beantwortet, die das Addon bewusst nicht selbst beantworten kann:
    wo ein Spieler ist, in welchem Team er steht, wohin die Bytes gehen. Etwa
    fünfzig.
  </Param>
  <Param name="Eine Resource anlegen">
    Eine `.tres`, die eine Designerin im Inspektor bearbeitet: Bewegungswerte,
    Schemata, Kataloge, Regeln, Stile, Oberflächen. Ganz ohne Code.
  </Param>
  <Param name="Unter einem Registry-Namen veröffentlichen">
    Duck-getypte Nahtstellen. Registriere ein Objekt mit einer Methode unter
    einem vereinbarten Namen, und zwei Addons arbeiten zusammen, ohne dass eines
    das andere importiert.
  </Param>
  <Param name="Eine Einstellung schichten">
    Jede `DotConfig`: exportierte Standardwerte, dann eine JSON- oder
    YAML-Datei, dann die Umgebung, dann die Kommandozeile.
  </Param>
</Params>

## Ableitungspunkte, nach Addon

Jeder davon ist eine abstrakte Basis mit einer kleinen, dokumentierten
Methodenmenge. Die mit **muss** markierten haben keinen brauchbaren Standard.

<Params>
  <Param name="DotTransport" type="dot-core">
    **`_create_server`**, **`_create_client`**, `_transport_name`,
    `_is_available`, `supports_web_clients`, `scheme`. `_is_available` wird vor
    der Nutzung geprüft, damit der Fehler beim Start „dieser Build kann nicht per
    ENet hosten“ lautet und nicht drei Aufrufe später ein Null-Peer ist.
  </Param>
  <Param name="DotJob" type="dot-core">
    **`_step`** (ein begrenztes Stück Arbeit; true, wenn mehr aussteht),
    `_progress` (0..1, oder **-1**, wenn es wirklich unbekannt ist — ein
    ehrlicher unbestimmter Balken ist besser als einer, der zurückspringt),
    `_setup`, `_teardown`, `is_thread_safe`.
  </Param>
  <Param name="DotConfig" type="dot-core">
    `env_prefix`, `cli_prefix`, `sensitive_keys`, `validate`.
  </Param>
  <Param name="DotLogSink" type="dot-core">
    Ein Handler für Logeinträge. `DotLog.add_sink(callable)` ist die
    Einzeiler-Variante.
  </Param>
  <Param name="DotCloudSource" type="dot-cloud">

    `fetch` muss nach `DotCloudStore.partial_path` schreiben, wo möglich ab

    Stelle, an der der Hash geprüft wird. Direkt ins Objektverzeichnis zu

  </Param>
  <Param name="DotAuthProvider" type="dot-auth">
    `_provider_name`, **`_handles(credential)`** (billig und rein strukturell),
    **`_authenticate(credential)`**, `_validate`. Ein Provider, der eine
    Credential beansprucht und sie dann ablehnt, hat entschieden: Der Server

  <Param name="DotNetBehaviour" type="dot-net">
    `_register_net_vars`, `_net_ready`, `_net_removed`, `_net_simulate`,

  <Param name="DotNetInput" type="dot-net">
    **`_write`**, **`_read`**, `_sanitise` (begrenzt alles, was ein Client

  <Param name="DotQueryProvider" type="dot-server">

  </Param>
  <Param name="DotVoteSource" type="dot-vote">
    `source_name`, **`choices`**, `current_id`, `supports_apply`, `apply`. Eine

  </Param>
  <Param name="DotPropTool" type="dot-props">

  <Param name="DotScreen / DotHudWidget" type="dot-ui">

  </Param>

## Callable-Haken

Das Addon weiß, wie die Arbeit geht; deine Welt kennt es nicht. Das sind die
Fragen, die es nicht raten will, gruppiert nach dem, was sie beantworten.

**Wohin die Bytes gehen.** `DotNetManager.send_fn`, `DotVoiceManager.send_fn`,
`DotVoiceRouter.send_fn`, `DotMapSyncHost.send_fn`, `DotMapSyncClient.send_fn`.
Keines dieser Addons besitzt einen Socket, und genau deshalb läuft `dot-net`
über eine Loopback-Verbindung, über einen echten Transport oder über deinen
eigenen.

**Wo etwas ist.** `DotMatch.position_fn`, `DotVoiceRouter.position_fn`,
`DotModTools.position_fn` / `teleport_fn`. `DotModTools` nimmt absichtlich
`Variant`-Positionen, damit 2D ein vollwertiger Anwendungsfall ist statt etwas,
das man umgehen muss.

**Wer als was zählt.** `DotDamageResolver.team_of`,
`DotVoiceRouter.team_fn` / `listener_filter`,
`DotVoteDirector.player_count_fn` / `is_admin_fn` / `is_spectator_fn` /
`voters_fn` / `weight_fn`, `DotRulesElimination.alive_fn`,
`DotModerationManager.key_for_peer`, `DotModTools.immunity_fn`.

**Was ein Spieler besitzt oder wie er heißen darf.**
`DotLoadoutManager.entitlement_source`, `DotPlatformHub.entitlement_source`,
`DotUserManager.name_filter`, `DotItemCatalogue.resolver`,
`DotAvatarCatalogue.resolver`.

**Wohin ein Schuss zurückspult.** `DotCombatManager.rewind_fn` / `restore_fn`.
Zwei Zeilen schalten die Lag-Kompensation ein; ohne sie werden Schüsse gegen die
Gegenwart aufgelöst — richtig für einen Listen-Server, falsch für jeden mit
Latenz.

**Alles Übrige.** `DotSpawnSelector.danger_fn` / `filter_fn`,
`DotDamageResolver.adjust`, `DotFpsMotor.surface_resolver`,
`DotPickupField.wants_fn` / `tags_fn`, `DotHudWidget.source`,
`DotStatBar.max_source`, `DotConVar.validator`, `DotConCommand.completer`,
`DotBackboneClient.roster_provider` / `stats_provider`,
`DotVoteDirector.announce_fn`, `DotVoteListSource.apply_fn`,
`DotVoiceManager.sink_factory`, `DotNetVar.read_fn` / `write_fn` /
`change_handler`, `DotNetSpawner.register_factory`.

<Callout type="warning" title="Ein nicht zugewiesener Haken ist kein Fehler">
Fast jeder davon hat ein vertretbares Verhalten im unbelegten Zustand — und
genau deshalb ist ein vergessener so schwer zu finden: Eine nicht verdrahtete
`entitlement_source` heißt, ein Spieler besitzt nichts; ein nicht zugewiesenes
`rewind_fn` heißt, es gibt keine Lag-Kompensation; ein nicht zugewiesenes
`key_for_peer` heißt, Strafen hängen am falschen Schlüssel. Das
`describe_lines()` jedes Addons meldet, was ihm fehlt — lies es, bevor du
annimmst, die Funktion sei kaputt.
</Callout>

## Ressourcen, die du anlegst

Kein Code, keine Unterklasse — eine `.tres` oder eine JSON-Datei.

— ohne dass eine der beiden Seiten die andere importiert.

| `dot_mute_source` | `DotModerationManager` | `DotVoiceRouter` |
| `dot_cloud_client` | `DotCloudClient` | der Lader von `dot-map`, der Spielwechsel von `dot-server`, der Katalog von `dot-user-avatar` |
| `dot_user_manager` | `DotUserManager` | `dot-server`, `dot-platform` |
| `dot_avatar_manager` | `DotAvatarManager` | `dot-platform` |
| `dot_auth_server` | `DotAuthServer` | `dot-server`, `dot-platform` |
| `dot_platform` | `DotPlatformHub` | `DotPlatformModule` |
| `dot_server`, `dot_console`, `dot_event_bus`, `dot_game_manager`, `dot_module_host`, `dot_admin_manager`, `dot_ban_manager`, `dot_chat_manager`, `dot_audit_log`, `dot_rcon_server`, `dot_query_server`, `dot_query_source`, `dot_a2s_server`, `dot_vote_manager` | `dot-server` | Module und dein eigener Code |
| `dot_client_link` | `DotClientLink` | der Client-Code eines Spiels |

`service_scope`, damit zwei von ihnen sich unter verschiedenen Namen
registrieren.

## Serverereignisse, die du abfangen oder verhindern kannst

`DotEventBus.hook_pre(name, callable)` läuft vor dem Ereignis und **kann es
abbrechen**; `hook_post` läuft danach. Hooks laufen in Registrierungsreihenfolge,
und ein Hook, der abbricht, stoppt die übrigen Pre-Hooks — ein abgebrochenes
Ereignis sollte nicht die Hälfte seiner Handler ausführen.

| Ereignis | Abbrechbar |
| --- | --- |
| `server_start`, `server_shutdown` | nein |
| `client_connect`, `client_disconnect` | nein |
| `client_spawn` | nein |
| `client_kicked` | nein |
| `player_chat` | **ja** |
| `player_command` | **ja** |
| `game_changing` | **ja** |
| `game_changed` | nein |
| `vote_started`, `vote_ended` | nein |
| `admin_action` | nein |

`declare(name, description)` registriert eigene Ereignisse — dadurch tauchen sie
im Konsolenbefehl `event_list` auf, und so findet eine Modulautorin heraus,
woran sie sich hängen kann, ohne den Quelltext zu lesen.

<Callout type="warning" title="`client_spawn` trägt `userid`, nicht `peer_id`">
Ein Modul, das die Sitzung über `peer_id` nachschlägt, bekommt jedes Mal null
und fügt niemanden hinzu — **still**, denn eine null-Sitzung ist etwas völlig
Legitimes. Das ist der am häufigsten wiederholte Fehler in der Geschichte dieser
Sammlung: Zwei verschiedene Spiele haben ihn ausgeliefert, und keines hat einen
Fehler gemeldet.
</Callout>
