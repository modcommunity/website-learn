Een server geeft een client een manifest; de client downloadt wat hij mist,
verifieert het en koppelt het aan — op Windows, macOS, Linux, Android, iOS en in
de browser.

```gdscript
var cloud := DotCloudClient.new()
add_child(cloud)

cloud.config = DotCloudConfig.new()
cloud.config.trusted_keys = {"default": PUBLIC_KEY_PEM}
await cloud.start()

cloud.phase_changed.connect(func(_p, text): status_label.text = text)
cloud.progress_changed.connect(func(p): bar.value = p.fraction * 100.0)

var res := await cloud.acquire("https://cdn.example.com/dm_arena/manifest.json")
if res.ok:
    get_tree().change_scene_to_file(res.value)
```

Publiceren gaat via een headless CLI die een **statische map** oplevert — een
`manifest.json` plus een `objects/`-boom — die elke webserver of CDN zonder
configuratie serveert:

```bash
godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    keygen --private keys/content.key --public keys/content.pub

godot --headless --path . --script addons/dot_cloud/publish/dot_cloud_cli.gd -- \
    publish --source content/dm_arena --out dist/dm_arena \
    --id dm_arena --version 1.2.0 --entry arena.tscn --key keys/content.key
```

## De twee beperkingen die alles hebben gevormd

**Godot kan een resourcepakket niet afkoppelen.** Niet langzaam, niet met een
truc — de API bestaat niet. Daarom krijgt elke contentset zijn eigen
geversioneerde pad, `res://<root>/<content_id>/<version>/`, en hoeft er nooit iets
vervangen te worden. "Ontladen" betekent verwijzingen loslaten, niet de
bestandstabel terugwinnen. Dat ene feit is waarom het wisselen van game tijdens
het draaien überhaupt werkt.

**Niet-ondertekende content is remote code execution.** Een Godot-pakket kan
scripts bevatten, dus een manifest bepaalt wat er wordt uitgevoerd.
`require_signed_manifests` staat standaard aan en de configuratie weigert te
valideren zonder vertrouwde sleutel. Je kunt het uitzetten voor een LAN of een
eigen server; hij waarschuwt elke keer.

## Wat het doet

- **Op inhoud geadresseerde cache.** Bestanden staan onder hun SHA-256, dus twee
  games die een asset delen downloaden het één keer, en opnieuw publiceren haalt
  alleen op wat veranderd is.
- **Hervatbare parallelle downloads.** Omschakelen tussen mirrors, hervatten via
  HTTP-ranges, een circuit breaker per bron, bandbreedtebeperking, en eerlijke
  voortgang en resttijd.
- **Drie bronnen.** HTTP/CDN, een lokale map (ontwikkeling, LAN, meegeleverde
  content), en in-band via de gameverbinding voor een server zonder webhosting.
- **Quotabewustzijn.** Opslagschattingen van de browser, mobiele plafonds, en
  least-recently-used-verdringing die nooit content verdringt die in gebruik is.

## Wat het aankoppelen controleert

Tussen download en aankoppelen wordt een pakket aan vier regels gehouden, die elk
voortkwamen uit een mislukking die iemand heeft gemeten:

- **Zijn `requires.json` wordt eerst gelezen.** De scripts van een pakket
  compileren tegen de add-ons van de host, dus een pakket dat een nieuwere add-on
  nodig had, kon halverwege het laden niet parsen. Nu wordt het geweigerd voordat
  er een script laadt, met *"Deze game heeft dot-net API-niveau 3 of nieuwer nodig;
  deze client heeft niveau 2."* — zie
  [add-on-API-niveaus](/learn/godot/addons/dot-core#addon-api-levels-dotaddonapi).
  `host_role` noemt de kant.
- **Een content-id mag zijn eigenaar noemen: `<owner>/<name>`.** `/` kan in geen
  van beide helften voorkomen, dus een sleutel met bereik `alice/*` is exact — een
  platgeslagen `alice_bob` kon `alice` + `bob_x` niet onderscheiden van
  `alice_bob` + `x`. Elk segment moet een slug zijn; een kaal id, wat elk
  first-partypakket is, valideert nog steeds.
- **Eén id kan geen twee dingen betekenen.** Een tweede manifest voor dezelfde
  `content_id@version` van een andere uitgever wordt geweigerd met
  `CODE_CONFLICT` in plaats van de aankoppeling van het eerste te krijgen — een
  pakket kan scripts bevatten, en "die van het eerste" is andermans code. Een
  gelijk manifest dat opnieuw van de lijn wordt gelezen, blijft een goedkope no-op.
- **Een aangekoppeld pakket registreert zijn eigen uid's, en mag die van niemand
  anders overnemen.** Een geïmporteerde asset (een `.glb`, een `.png`) verwijst
  per UID naar zijn buren, en dat overleeft het elders aankoppelen niet; de
  aankoppelaar laat elke UID naar de aangekoppelde kopie wijzen. Een UID die de
  host al heeft, wordt geweigerd en gemeld, anders zou elke `load("uid://…")` in de
  build naar gedownloade content kunnen worden omgeleid.

<Callout type="warning" title="Geïmporteerde uitvoer wordt onder `_imported/` geleverd, nooit onder `.godot/`">
Een gepubliceerd pakket bevat de geïmporteerde uitvoer van de engine, en die
stond vroeger op zijn echte pad, `.godot/imported/`. Linux leest dat probleemloos
terug; **een webexport kan het niet**, en de hele game weigerde in de browser te
starten. Uitvoer wordt nu onder `_imported/` geleverd, met elke `.import`-markering
herschreven zodat hij noemt waar de uitvoer terecht is gekomen. Ontbrekende art in
een aangekoppeld pakket verschijnt anders alleen als waarschuwingen — het pakket
verifieert, koppelt aan en laadt zonder zijn texturen.
</Callout>

## Waar een game aansluit

<Params>
  <Param name="Subklasse van DotCloudSource">
    `source_name()`, `is_supported()`, `can_serve(manifest)`, `fetch(...)`. Er
    worden er drie meegeleverd — `DotCloudSourceHttp`, `DotCloudSourceLocal`,
    `DotCloudSourceNetchan` — en de vierde is van jou: een torrent, een
    platformspecifiek CDN, een generator van ondertekende S3-URL's.

    Een `fetch` **moet** naar `DotCloudStore.partial_path` voor de hash van het
    bestand schrijven, waar mogelijk hervatten vanaf `partial_size`, en afronden
    via `commit_partial`. Dat is de enige plek waar de hash wordt geverifieerd, en
    direct in de objectenmap schrijven is precies hoe ongeverifieerde content
    aangekoppeld raakt.
  </Param>
  <Param name="can_serve() tegenover is_supported()">
    Het onderscheid verdient zijn plek. Een bron kan volstrekt gezond zijn en toch
    geen manier hebben om *dit* manifest te bereiken — een HTTP-bron zonder
    `base_urls` tegenover een manifest zonder mirrors. Een mislukking teruggeven
    uit `can_serve` betekent "sla me over voor dit manifest, en dit is waarom", en
    telt **niet** mee voor de circuit breaker.
  </Param>
  <Param name="priority" type="int">
    Op elke bron. Lager gaat eerst; de in-band terugval staat bewust achteraan.
  </Param>
  <Param name="DotCloudConfig">
    `trusted_keys`, `require_signed_manifests`, `cache_bytes`,
    `mobile_cache_bytes`, `web_quota_fraction`, `parallel_downloads`,
    `max_attempts_per_file`, `throttle_bytes_per_sec`, `file_timeout_sec`, `cache_dir`,
    `verify_before_mount`, `verify_cache_on_start`, `resume_downloads`, `enforce_mount_prefix`. Gelaagd zoals elke `DotConfig`.
  </Param>
  <Param name="manifest_url_template / manifest_url_fallbacks" type="DotCloudClient">
    Waar een manifest wordt opgevraagd, vanuit een basis-URL, een id en een versie. De standaard is `{base}/{id}/{version}/manifest.json`, wat de site publiceert; `manifest_url_fallbacks` noemt andere vormen die daarna per basis worden geprobeerd, omdat één bron pakketten kan bevatten die onder twee indelingen zijn gepubliceerd en ze allemaal opnieuw publiceren geen voorwaarde is om te kunnen starten.
  </Param>
  <Param name="Signalen">
    Op `DotCloudClient`: `phase_changed`, `progress_changed`, `content_ready`, `content_released`, `failed`. Detail per bestand zit op de downloader: `file_finished`, `sync_finished`.
  </Param>
</Params>

## De contentinterface die andere add-ons verwachten

Registreer een `DotCloudClient` en hij publiceert zichzelf onder
`dot_cloud_client`. De lader van `dot-map` en de gamewissel van `dot-server`
bereiken hem via die naam en roepen aan:

```gdscript
ensure(content_id: String, version: String) -> DotResult
is_mounted(content_id: String, version: String) -> bool
```

De meeste add-ons bereiken ze via `DotContent` in
[`dot-core`](/learn/godot/addons/dot-core#downloadable-content-dotcontent), de
ene gedeelde aanroeper — waardoor avatar-onderdelen, props, NPC's, voertuigen en
items die content noemen die nu ook echt ophalen.

<Callout type="warning" title="Een afwezige cloudclient is een legitieme configuratie">
Elke aanroepplek behandelt "geen `dot_cloud_client`" als "deze uitrol levert zijn
content mee in de build" — wat een legitieme keuze is voor je eigen game, en dus niet
te onderscheiden is van een client die zich niet heeft geregistreerd. De eigen uitrol van TMC levert helemaal geen content mee in zijn build: elke game, elke geïmporteerde map en de lobby is een pakket dat deze add-on ophaalt. Als een
geleverde map of game stilletjes niets doet, kijk dan eerst in de registry.
</Callout>
